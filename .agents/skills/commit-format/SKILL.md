# Commit Format Rules

## Требования к сообщениям коммитов

Все коммиты должны строго соответствовать формату:

```
<type>(<scope>): <описание>

[тело]
```

### Type (обязательно)

- `feat` — новая функциональность для пользователя
- `fix` — исправление ошибки
- `docs` — документация
- `style` — форматирование (отступы, точки с запятой и т.д.)
- `refactor` — рефакторинг без изменения поведения
- `test` — добавление тестов
- `chore` — рутинные задачи (build, deps, config)

### Заголовок (первая строка)

- Максимум **50 символов**
- С заглавной буквы
- Без точки в конце
- Повелительное наклонение («добавить», «исправить», «удалить»)
- На русском языке
- Без эмодзи и смайликов

### Тело (опционально)

- Отделяется пустой строкой от заголовка
- Максимум **72 символа** на строку
- Отвечает на вопросы **«что»** и **«почему»**, а не «как»

### Scope (опционально)

Уточняет область изменений:
- `deps` — зависимости
- `docker` — Dockerfile / compose
- `docs` — документация
- `config` — конфигурация
- `reports` — отчёты
- `logging` — логирование

### Примеры

```
feat: добавить поддержку terrain_hills в симуляцию

fix(docker): убрать syntax-директиву из Dockerfile

docs: добавить план оптимизации CPU fallback

refactor: заменить print на _log в plugin_manager

chore(deps): добавить numba в requirements.txt
```
