## 1. Что такое Docker

### 1.1. Простая аналогия

Представьте контейнер для еды:

- Вы кладёте еду в контейнер
- Контейнер герметичен -- ничего не проливается
- Вы можете взять контейнер с собой куда угодно
- Еда внутри всегда одинаковая, независимо от того, где вы открываете контейнер

Docker работает так же. Он упаковывает приложение со всеми зависимостями в изолированный контейнер.

### 1.2. Техническое определение

Docker -- это платформа для контейнеризации. Контейнер -- это изолированная среда, которая содержит всё необходимое для работы приложения: код, библиотеки, системные утилиты, настройки.

Преимущества:
- Одинаковое поведение на любом компьютере
- Быстрое развёртывание
- Изоляция от основной системы
- Лёгкое удаление

## 2. Зачем Docker для ROS2

### 2.1. Проблема без Docker

Установка ROS2 вручную:

- Долгая установка (часы на загрузку пакетов)
- Конфликты версий с другими пакетами
- "На моём компьютере работает!" -- у других может не работать
- Сложно удалить полностью

### 2.2. Решение с Docker

Наш образ содержит:

- ROS2 Jazzy уже установлен
- Gazebo уже настроен
- Все пакеты уже собраны
- Работает на Ubuntu, Windows, macOS
- Можно удалить за 1 команду

## 3. Dockerfile проекта

Dockerfile описывает, как собирается образ. Наш проект использует многоступенчатую сборку (multi-stage build):

Этап 1: base-system -- базовые системные зависимости
Этап 2: ros-core -- основные пакеты ROS2
Этап 3: ros-control -- пакеты управления
Этап 4: ros-simulation -- Gazebo и симуляция
Этап 5: ros-navigation -- Nav2, SLAM
Этап 6: ros-vision -- камеры, сенсоры
Этап 7: ros-tools -- инструменты разработки
Этап 8: python-deps -- Python зависимости
Этап 9: workspace -- копирование и сборка проекта
Этап 10: final -- финальный образ

Кэширование ускоряет повторные сборки:
- APT кэш -- /var/cache/apt
- pip кэш -- /root/.cache/pip
- ccache кэш -- /root/.ccache

## 4. Docker Compose

Docker Compose позволяет описать конфигурацию контейнера в YAML-файле.

Наш compose.yml определяет:

- Сервис simulator с GUI поддержкой (X11 forwarding)
- Host network для ROS2 связи
- Privileged mode для доступа к ресурсам
- Ограничения ресурсов (24G RAM, 12 CPU)
- Тома для логов, данных и исходного кода
- Переменные окружения (ROS_DISTRO, RMW_IMPLEMENTATION, GAZEBO_RESOURCE_PATH)

## 5. Запуск проекта

### 5.1. Сборка образа

```bash
cd src/docker
docker compose build
```

Первая сборка занимает 15-30 минут. Повторная -- 30-60 секунд благодаря кэшированию.

### 5.2. Запуск контейнера

```bash
docker compose up -d
```

### 5.3. Вход в контейнер

```bash
docker compose exec simulator bash
```

### 5.4. Источник ROS2

```bash
source /opt/ros/jazzy/setup.bash
source /root/ws/install/setup.bash
```

## 7. FAQ

### Сколько места занимает образ?

Около 10-15 ГБ после полной сборки.

### Можно ли остановить контейнер?

Да. docker compose down останавливает и удаляет контейнер.

### Как удалить всё?

```bash
docker compose down
docker system prune -a
```

### Почему сборка такая долгая?

Первая сборка загружает и устанавливает сотни пакетов ROS2. Повторные сборки используют кэш и занимают 30-60 секунд.

### Что делать, если Docker не запускается?

- Убедитесь, что Docker установлен: docker --version
- Проверьте, что демон запущен: systemctl status docker
- На Linux: добавьте пользователя в группу docker: sudo usermod -aG docker $USER

### Можно ли запустить GUI из контейнера?

Да. Наш compose.yml настроен для X11 forwarding. Gazebo GUI будет отображаться на хосте.

### Как обновить образ?

```bash
docker compose down
docker compose build
docker compose up -d
```
