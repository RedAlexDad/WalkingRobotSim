## 1. Что такое топики

### 1.1. Простая аналогия

Представьте себе телевизионные каналы:

- Первый канал -- показывает новости
- Спорт -- показывает матчи
- Кухня ТВ -- показывает рецепты

Вы -- телезритель. Вы можете включить Первый канал и смотреть новости, переключиться на Спорт, или выключить телевизор -- каналы продолжают вещать.

Топики в ROS2 работают так же!

```
+-------------+
|   Узел 1    | ----> [Топик /news] ----> Узел А (подписан)
| (Publisher) |                         Узел Б (подписан)
+-------------+                         Узел В (не подписан)
```

### 1.2. Технические детали

Топик (Topic) -- это именованный канал, через который узлы обмениваются сообщениями.

Характеристики топика:
- Имя -- например, /camera/image, /cmd_vel
- Тип сообщения -- что именно передаётся
- Односторонняя связь -- данные идут в одну сторону
- Publish/Subscribe -- кто хочет, тот подписывается

### 1.3. Именование топиков

Правила именования:

Правильно:
- /cmd_vel
- /camera/image
- /robot1/joint_states
- /battery/level

Неправильно:
- cmd_vel (без начального слэша)
- camera/image (без первого слэша)
- /robot1/Joint_States (заглавные буквы)
- /battery-level (дефисы)

Рекомендации:
- Начинайте с /
- Используйте нижние подчёркивания _
- Делайте имена понятными: /left_motor_speed лучше, чем /lms

## 2. Просмотр топиков

### 2.1. Список всех топиков

```bash
ros2 topic list
```

Пример вывода:
```
/camera/image
/cmd_vel
/imu/data
/joint_states
/odom
/robot_mode
/clock
/parameter_events
/rosout
```

### 2.2. Информация о топике

```bash
ros2 topic info /cmd_vel
```

Пример вывода:
```
Type: geometry_msgs/msg/Twist
Publisher count: 1
Subscriber count: 2
```

Это значит:
- Тип сообщения: Twist (команда движения)
- 1 издатель -- кто-то публикует команды
- 2 подписчика -- два узла получают эти команды

### 2.3. Тип сообщения

```bash
ros2 topic type /cmd_vel
```

Вывод: geometry_msgs/msg/Twist

## 3. Подписка на топики

### 3.1. Просмотр сообщений в реальном времени

```bash
ros2 topic echo /odom
```

Пример вывода:
```
header:
  stamp:
    sec: 1234567890
    nanosec: 123456789
  frame_id: "odom"
pose:
  pose:
    position:
      x: 0.0
      y: 0.0
      z: 0.0
    orientation:
      x: 0.0
      y: 0.0
      z: 0.0
      w: 1.0
```

### 3.2. Показать только одно сообщение

```bash
ros2 topic echo /odom --once
```

### 3.3. Показать N сообщений

```bash
ros2 topic echo /odom -n 5
```

## 4. Публикация сообщений

### 4.1. Разовая публикация

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.5, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"
```

### 4.2. Постоянная публикация

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.1, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}" -r 10
```

Команда -r 10 означает публикацию 10 раз в секунду.

### 4.3. Остановка робота

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}" -1
```

## 5. Типы сообщений

### 5.1. geometry_msgs/msg/Twist

Команда скорости. Используется для управления движением.

Поля:
- linear.x -- скорость вперёд/назад
- linear.y -- скорость влево/вправо
- linear.z -- скорость вверх/вниз
- angular.x -- вращение вокруг X (roll)
- angular.y -- вращение вокруг Y (pitch)
- angular.z -- вращение вокруг Z (yaw)

### 5.2. sensor_msgs/msg/JointState

Состояние сочленений робота.

Поля:
- name -- массив имён сочленений
- position -- массив текущих позиций
- velocity -- массив скоростей
- effort -- массив усилий

### 5.3. nav_msgs/msg/Odometry

Информация о положении и скорости робота.

Поля:
- header -- метка времени и frame_id
- pose -- позиция и ориентация
- twist -- линейная и угловая скорость

### 5.4. sensor_msgs/msg/Imu

Данные инерциального измерительного блока.

Поля:
- orientation -- кватернион ориентации
- angular_velocity -- угловая скорость
- linear_acceleration -- линейное ускорение

## 6. Практика

### Задание 1: Просмотр топиков

```bash
# Запустите симуляцию
cd src/docker
docker compose up -d
docker compose exec simulator bash
source /opt/ros/jazzy/setup.bash
source /root/ws/install/setup.bash

# Посмотрите все топики
ros2 topic list

# Посчитайте количество топиков
ros2 topic list | wc -l
```

### Задание 2: Подписка на топик

```bash
# Подпишитесь на одометрию
ros2 topic echo /robot1/odom

# Подпишитесь на состояние сочленений
ros2 topic echo /robot1/joint_states
```

### Задание 3: Публикация команды

```bash
# Переключите робота в режим STAND
ros2 topic pub /robot1/robot_mode quadropted_msgs/msg/RobotModeCommand "{mode: 'STAND', robot_id: 1}"

# Переключите в режим TROT
ros2 topic pub /robot1/robot_mode quadropted_msgs/msg/RobotModeCommand "{mode: 'TROT', robot_id: 1}"
```

## 7. FAQ

### Чем топик отличается от сервиса?

Топик -- односторонняя связь (publish/subscribe), без подтверждения. Сервис -- двусторонняя связь (запрос/ответ), с подтверждением.

### Что будет, если публиковать в топик без подписчиков?

Сообщения будут публиковаться, но их никто не получит. ROS2 может выдать предупреждение.

### Может ли узел быть и Publisher, и Subscriber?

Да. Один узел может публиковать в одни топики и подписываться на другие.

### Как узнать структуру сообщения?

ros2 interface show geometry_msgs/msg/Twist
