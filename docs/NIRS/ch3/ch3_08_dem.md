# Глава 3. Разработка модуля Elevation Mapping и terrain-aware планирования

## 3.8 Цифровая модель высот (DEM) и gradient поверхности

Цифровая модель высот (DEM) является центральным элементом разработанного модуля, предоставляя информацию о рельефе для всех последующих вычислений проходимости и планирования пути. DEM строится на основе отфильтрованных ground-точек с использованием GPU-ускоренного модуля elevation_mapping_cupy, что позволяет обрабатывать данные в реальном времени. Каждая ячейка карты содержит не только среднюю высоту, но и дисперсию, количество наблюдений и временные метки, что позволяет оценивать достоверность данных. На основе DEM вычисляется gradient поверхности — наклон в каждой ячейке, необходимый для расчёта traversability. В данном разделе описывается процесс построения DEM, её характеристики и метод вычисления gradient поверхности.

### 3.8.1 Построение DEM и структура GridMap

Цифровая модель высот (Digital Elevation Model, DEM) строится модулем elevation_mapping_cupy в реальном времени на GPU [5, 11, 14, 15]. Характеристики карты высот приведены в Таблице 3.3.

Таблица 3.3 — Характеристики карты высот

| Параметр           | Значение  | Обоснование                                                                  |
| ------------------ | --------- | ---------------------------------------------------------------------------- |
| Размер карты       | 20 × 20 м | Достаточен для планирования пути с учётом дальности LiDAR (10 м)             |
| Разрешение         | 0,1 м     | Компромисс между детализацией и производительностью (200×200 = 40 000 ячеек) |
| Частота обновления | 10 Гц     | Совпадает с частотой LiDAR                                                   |
| Система координат  | odom      | Карта центрируется относительно робота и перемещается вместе с ним           |
| Число слоёв        | 3         | elevation, variance, traversability                                          |

Карта высот хранится в формате `grid_map::GridMap` — библиотеки, предоставляющей многослойную сетку данных с поддержкой ROS 2 [1]. Слой elevation хранит средневзвешенную высоту поверхности (float32, метры). Слой variance хранит дисперсию оценки высоты (чем больше измерений, тем ниже дисперсия). Слой traversability хранит проходимость от 0,0 до 1,0, вычисляемую на основе elevation и gradient.

### 3.8.2 Алгоритм обновления карты и постобработка

При поступлении нового облака точек карта обновляется по следующему алгоритму, реализованному на CUDA.

Шаг 1 — проецирование точек: каждая точка преобразуется из фрейма сенсора в фрейм карты с использованием TF-трансформаций. Результат — массив координат (x, y, z) в системе координат карты.

Шаг 2 — определение ячеек: для каждой точки определяется ячейка карты по формулам, приведённым в Главе 2 (раздел 2.5.2).

Шаг 3 — взвешенное усреднение: для каждой ячейки вычисляется новое значение высоты как взвешенное среднее всех измерений (Глава 2, раздел 2.5.3). Вес измерения определяется дисперсией: w_measured = 1,0 / sensor_noise_stddev².

Шаг 4 — обновление дисперсии: дисперсия ячейки обновляется по правилу фильтра Калмана (Глава 2, раздел 2.5.4). При каждом подтверждении (новом измерении) дисперсия уменьшается [4].

После обновления карты применяются фильтры постобработки: медианный фильтр (замена значения в ячейке на медиану в окне 3×3, удаляет импульсный шум, сохраняя границы объектов), фильтр по уверенности (ячейки с высокой дисперсией заполняются интерполяцией от соседних ячеек для закрытия мелких пропусков в данных) и фильтр выбросов (если высота ячейки отличается от среднего по окну 3×3 более чем на 3 стандартных отклонения, ячейка помечается как недостоверная) [1].

### 3.8.3 Gradient и Roughness поверхности

Gradient (уклон) поверхности вычисляется плагином `surface_gradient.py` (загружаемым через `postprocessor_plugins: [surface_gradient, roughness, cost_function]`). Математическая модель вычисления gradient методом PCA и расчёта roughness приведены в Главе 2 (разделы 2.5.5 и 2.5.6).

Значение gradient нормализовано: 0,0 — горизонтальная поверхность, 1,0 — вертикальная стена.

Интерпретация roughness: менее 0,01 м — ровная дорога; 0,01–0,03 м — гладкий асфальт; 0,03–0,06 м — трава, гравий; 0,06–0,10 м — мелкие камни; более 0,10 м — крупные камни. В отличие от встроенной реализации grid_map, roughness.py работает с numpy, что позволяет легко модифицировать алгоритм без перекомпиляции.

### 3.8.4 Производительность GPU и CPU

Благодаря реализации на CuPy (CUDA Python), основные вычислительные операции выполняются на GPU. На NVIDIA GTX 1650 Ti (CUDA 12.8, 4 ГБ): проецирование 5760 точек — 0,2 мс (GPU) против 2,1 мс (CPU); обновление 40 000 ячеек — 0,5 мс против 5,3 мс; вычисление gradient — 0,3 мс против 3,1 мс; visibility cleanup — 0,8 мс против 8,5 мс. Общее время обработки одного кадра составляет менее 2 мс, что даёт ускорение примерно в 10× относительно CPU [11, 14, 19].

Для конфигураций без GPU (Dockerfile.cpu) все вычисления выполняются на numpy. Частота обновления карты составляет около 5 Гц (против 10 Гц на GPU). Плагины gradient, roughness и cost работают на CPU в обоих режимах, их производительность идентична. CPU-режим пригоден для отладки конфигурации и разработки плагинов, но не для полноценной real-time навигации.
