# Глава 3. Разработка модуля Elevation Mapping и terrain-aware планирования

## 3.12 Оценка качества и метрики

Количественная оценка качества разработанного модуля необходима для объективного сравнения различных конфигураций и проверки соответствия требованиям. Для оценки точности карты высот используются стандартные метрики регрессии, позволяющие сравнить построенную DEM с эталонной моделью. Качество traversability оценивается на основе способности различать проходимые и непроходимые участки, а также согласованности с экспертной оценкой. Дополнительно измеряется производительность системы в реальном времени и задержка обработки данных. В данном разделе приводится перечень используемых метрик, методика их вычисления и полученные результаты.

### 3.12.1 Метрики точности и производительности

Для количественной оценки качества построенной карты высот используются стандартные метрики регрессии (RMSE, MAE, Max Error, Coverage), математические определения которых приведены в Главе 2 (раздел 2.8.1).

Ground truth для тестовых миров Gazebo получается из аналитической функции высоты $z = f(x, y)$. Для Scenario 1: $z = 0$ (const). Для Scenario 3: $z(x, y) = A \sin(\omega_x x) \cos(\omega_y y)$. Для Scenario 4: комбинация функций с кусочной интерполяцией.

Метрики производительности: FPS карты (≥ 10 Гц), Latency (< 100 мс), GPU memory (< 2 ГБ), CPU usage (< 50%). Для CPU-режима: FPS ≥ 5 Гц, CPU < 80%.

### 3.12.2 Метрики навигации

Для оценки эффективности навигации используются метрики, формально определённые в Главе 2 (раздел 2.8.4): длина пути, время прохождения, средняя скорость, энергозатраты, количество экстренных остановок.

### 3.12.3 Инструменты и сравнение с baseline

Для автоматического сбора метрик разработан скрипт `compute_metrics.py` с функциями: `read_rosbag` (топики `/elevation_map`, `/ground_truth`, `/odom`, `/joint_states`), `compute_height_metrics` (RMSE, MAE, Max Error, Coverage), `compute_performance_metrics` (FPS, Latency, GPU/CPU usage), `compute_navigation_metrics` (длина пути, время, скорость, энергозатраты, остановки). Результаты — в CSV.

Для оценки terrain-aware подхода проводится сравнение с baseline: baseline использует occupancy costmap, фиксированные параметры походки (step_height = 0,04 м, frequency = 2,0 Гц) и A* без учёта рельефа [3]. Terrain-aware режим использует traversability costmap, адаптивные параметры и выбор пути с учётом безопасности. Ожидается: terrain-aware — RMSE на 10–20% ниже, остановок на 50–100% меньше, энергозатраты на 15–25% ниже; baseline — время прохождения на 10–20% меньше.
