# Глава 3. Разработка модуля Elevation Mapping и terrain-aware планирования

## 3.6 Фильтрация облака точек и параметры сенсора

### 3.6.1 Параметры elevation_mapping_cupy

Конфигурация модуля задаётся в двух файлах:

- **core_param.yaml**: основные параметры, общие для всех роботов.
- **go2_lidar3d.yaml**: robot-specific параметры для Unitree Go2.

**core_param.yaml:**

```yaml
# Основные параметры карты высот
resolution: 0.1               # Разрешение ячейки карты [м]
map_length: 20.0              # Размер карты [м]
min_valid_distance: 0.3       # Минимальное расстояние точки [м]
max_ray_length: 10.0          # Максимальная длина луча [м]
max_height_range: 10.5        # Максимальный диапазон высот [м]

# Параметры RAM-фильтра высоты
ramped_height_range_a: 0.3    # Коэффициент наклона порога
ramped_height_range_b: 1.0    # Расстояние излома [м]
ramped_height_range_c: 0.2    # Минимальный порог высоты [м]

# Параметры visibility cleanup
cleanup_step: 0.1             # Шаг очистки (уверенность)
cleanup_footprint: 1          # Радиус очистки [ячеек]

# Параметры фильтрации точек
mahalanobis_thresh: 2.0       # Порог фильтрации Махаланобиса
sensor_noise_stddev: 0.01     # Стандартное отклонение шума сенсора
```

**go2_lidar3d.yaml:**

### 3.6.2 Фильтрация тела робота

LiDAR установлен на корпусе робота в позиции (0.22, 0, 0.095)
относительно base_link. Вертикальный угол обзора ±15° означает,
что при расстоянии менее 30 см лучи попадают на корпус робота.

Параметр `min_valid_distance: 0.3` отбрасывает все точки ближе 30 см,
что исключает отрисовку корпуса и крышки робота на карте высот.

Без этого параметра (значение 0.1 по умолчанию) на карте высот
отображаются артефакты в виде возвышения вокруг позиции робота,
что приводит к ложной классификации местности как непроходимой.

### 3.6.3 Ограничение дальности

LiDAR имеет физическое ограничение дальности 12 м. Для ray tracing
(visibility cleanup) установлен `max_ray_length: 10.0`, что обеспечивает:

1. **Корректную обработку видимости**: точки за пределами 10 м
   не используются для visibility cleanup, так как их точность
   недостаточна.

2. **Оптимизацию производительности**: сокращение количества
   обрабатываемых точек на периферии снижает нагрузку на GPU.

3. **Фокус на рабочей зоне**: карта имеет размер 20×20 м, и
   обработка точек за пределами 10 м от робота не даёт существенного
   улучшения качества карты.

### 3.6.4 RAM-фильтр высоты (Adaptive Height Filter)

RAM-фильтр (Ramped Adaptive Maximum height) реализует адаптивный
порог высоты, зависящий от расстояния до точки:

```
z_max(d) = max(d - ramped_height_range_b, 0) * ramped_height_range_a
           + ramped_height_range_c
```

где d — расстояние от сенсора до точки, z_max — максимальная
допустимая высота точки над сенсором.

**Принцип работы:**

- На близких расстояниях (d < b): порог = c (минимальный).
- На дальних расстояниях (d > b): порог линейно растёт с
  коэффициентом a.

**Пример для a=0.3, b=1.0, c=0.2:**

| Расстояние | Порог высоты | Что отбрасывается |
|-----------|-------------|-------------------|
| d=0.3 м | 0.2 м | Всё выше 20 см над сенсором |
| d=1.0 м | 0.2 м | Всё выше 20 см |
| d=2.0 м | 0.5 м | Всё выше 50 см |
| d=5.0 м | 1.4 м | Всё выше 1.4 м |
| d=10.0 м | 2.9 м | Всё выше 2.9 м |

Это позволяет:

- На близких расстояниях: отбрасывать потолки и нависающие объекты.
- На дальних расстояниях: учитывать естественный рельеф (холмы).

### 3.6.5 Visibility Cleanup

Visibility cleanup — алгоритм, реализованный на CUDA, который
корректирует карту высот на основе анализа видимости.

**Принцип работы:**

Для каждой ячейки карты на расстоянии d от сенсора:
1. Определяется, находится ли ячейка на прямой видимости
   (line of sight) между сенсором и точкой измерения.
2. Если ячейка находится на линии видимости, её уверенность
   уменьшается на `cleanup_step` (0.1).
3. При продолжении поступления измерений, подтверждающих
   наличие объекта в данной ячейке, уверенность восстанавливается.

**Эффект:**

- Динамические объекты (движущиеся роботы, люди) автоматически
  удаляются с карты через несколько кадров.
- Шумовые измерения не создают ложных объектов на карте.
- Точность карты на границах объектов повышается.

### 3.6.6 Фильтрация выбросов Махаланобиса

Для дополнительной фильтрации используется критерий Махаланобиса:

```
mahalanobis_distance = |z_measured - z_expected| / sqrt(variance)
if mahalanobis_distance > mahalanobis_thresh:
    reject_point()
```

Параметр `mahalanobis_thresh: 2.0` означает, что отбрасываются точки,
отклоняющиеся от ожидаемой высоты более чем на 2 стандартных отклонения.
Это удаляет редкие выбросы, не затрагивая основную поверхность.

### 3.6.7 Комплексная фильтрация: алгоритм обработки точки

При поступлении нового облака точек каждая точка проходит
следующие этапы фильтрации:

```
Вход: точка (x, y, z) в фрейме сенсора

1. Проверка min_valid_distance
   if distance(x,y,z) < 0.3:
       reject → следующая точка

2. Проверка max_ray_length  
   if distance(x,y,z) > 10.0:
       reject → следующая точка

3. Проверка ramped_height_range
   if z > z_max(distance):
       reject → следующая точка

4. Проецирование в фрейм карты
   (x_map, y_map, z_map) = transform(x, y, z, sensor_frame → map_frame)

5. Проверка Махаланобиса
   if mahalanobis_distance(z_map, elevation_map[x_map][y_map]) > 2.0:
       reject → следующая точка

6. Обновление карты
   elevation_map[x_map][y_map] = update_height(z_map)

Выход: обновлённая карта высот
```
