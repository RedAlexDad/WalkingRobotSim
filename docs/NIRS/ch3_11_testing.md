# Глава 3. Разработка модуля Elevation Mapping и terrain-aware планирования

## 3.11 Тестирование в симуляции Gazebo

### 3.11.1 Сценарии тестирования

Для валидации разработанного модуля созданы тестовые миры Gazebo
с различными типами рельефа:

**Сценарий 1: Ровная дорога (baseline)**

Плоская поверхность без препятствий (z = const).

*Цель:* Проверка базовой работы elevation mapping, фильтрации тела
робота и корректности TF трансформаций.

*Ожидаемый результат:*
- RMSE карты высот < 0.02 м.
- Все 5760 точек LiDAR корректно проецируются.
- Traversability = 1.0 для всех ячеек.
- Робот движется с максимальной скоростью (0.5 м/с).

**Сценарий 2: Лёгкие неровности**

Поверхность с мелкими неровностями: трава, гравий, мелкие камни
(h = 0.02–0.05 м).

*Цель:* Проверка ground segmentation и базовой traversability.

*Ожидаемый результат:*
- Ground segmentation выделяет > 90% точек как ground.
- Traversability > 0.7 (проходимо, Moderate).
- Высота шага = 0.04–0.08 м.

**Сценарий 3: Холмы и подъёмы**

Синусоидальный рельеф с перепадами высот до 0.5 м:
```
z(x, y) = A * sin(ωx * x) * cos(ωy * y)
```

*Параметры:*
- A = 0.3 м (амплитуда).
- ωx = ωy = 0.5 рад/м (пространственная частота).

*Цель:* Проверка gradient и slope cost.

*Ожидаемый результат:*
- Gradient корректно вычисляется для наклонных поверхностей.
- Slope cost пропорционален углу наклона.
- Planner выбирает путь через долины между холмами.

**Сценарий 4: Смешанный рельеф**

Комбинация ровных участков, травы, камней и холмов.

*Цель:* Проверка terrain-aware планирования и адаптации походки
в комплексном сценарии.

*Ожидаемый результат:*
- Planner выбирает безопасный маршрут с учётом рельефа.
- Походка адаптируется при смене типа поверхности.
- Робот огибает непроходимые участки.

**Сценарий 5: Препятствия**

Ящики, бордюры, ступени (h = 0.1–0.3 м).

*Цель:* Проверка обнаружения no-go зон и корректной классификации.

*Ожидаемый результат:*
- Препятствия высотой > 0.2 м классифицируются как Unsafe.
- Робот останавливается перед препятствием с запасом не менее 0.3 м.

### 3.11.2 Процедура тестирования

Для каждого сценария выполняется следующая процедура:

**Подготовка:**

1. Запуск симуляции Gazebo с соответствующим миром.
2. Запуск elevation_mapping_node с RViz для визуализации.
3. Настройка записи rosbag.

**Выполнение:**

4. Робот выполняет движение по заданному маршруту (набор waypoints).
5. Во время движения записываются:
   - PointCloud2 от LiDAR.
   - Elevation map (GridMessage).
   - Ground / obstacle облака.
   - Параметры походки (gait params).
   - Odometry (одометрия).
   - Joint states (состояния суставов).

**Анализ:**

6. Воспроизведение rosbag.
7. Вычисление метрик качества.
8. Визуальный анализ в RViz.

**Критерии успеха:**

Для прохождения сценария необходимо:
- Отсутствие ошибок в ROS-нодах.
- RMSE карты высот в пределах допуска.
- Отсутствие экстренных остановок (кроме Scenario 5).
- Корректное обнаружение no-go зон.

### 3.11.3 Результаты тестирования

**Stage 0: Валидация elevation_mapping_cupy (модульные тесты)**

- Все 41 модульных тестов пакета elevation_mapping_cupy пройдены.
- Synthetic depth demo работает корректно: карта высот строится
  за < 2 мс на GPU.
- GPU-ядра (CuPy) выполняются без ошибок на GTX 1650 Ti.
- Потребление GPU памяти: ~1.2 ГБ (из 4 ГБ доступных).

**Stage 1: Docker-интеграция**

- Оба контейнера собираются и запускаются без ошибок.
- Cyclone DDS discovery работает стабильно с отключённым SHM.
- TF relay корректно передаёт трансформации между контейнерами.
- RViz в GPU-контейнере отображает все топики.

**Stage 2: LiDAR → elevation_map pipeline**

- PointCloud2 от LiDAR успешно принимается elevation_mapping_node.
- Elevation map публикуется с кадром odom и разрешением 0.1 м.
- Слои elevation, variance, traversability обновляются на каждом кадре.
- Фильтрация тела робота (min_valid_distance=0.3) исключает артефакты.
- Частота публикации: 10 Гц (стабильно).

**Stage 3: Ground segmentation**

- Ground Plane Fitting корректно разделяет облако точек.
- На ровной поверхности (Scenario 1): precision > 98%, recall > 95%.
- На холмистой поверхности (Scenario 3): precision > 95%, recall > 90%.
- Время обработки: < 5 мс на кадр (CPU, Python + numpy).

**Stage 4: Traversability**

- Gradient корректно вычисляется для наклонных поверхностей.
- Классификация safe/medium/unsafe работает в соответствии с
  заданными порогами.
- Cost map корректно маркирует препятствия как no-go зоны.

**Stage 5: Адаптация походки**

- Параметры походки изменяются при смене типа поверхности.
- Переходы между режимами плавные (экспоненциальное сглаживание).
- Робот корректно останавливается перед no-go зоной.

### 3.11.5 Анализ ошибок

Наиболее частые ошибки, выявленные в ходе тестирования:

1. **Недостаточная точность на дальних расстояниях**:
   На расстоянии > 8 м разрешение LiDAR (вертикальный шаг ~1.875°)
   даёт вертикальное разрешение ~26 см. Это приводит к повышенной
   ошибке на удалённых участках карты.

2. **Потеря ground на крутых склонах (> 20°)**:
   Ground Plane Fitting с 3 итерациями может потерять часть ground
   точек на крутых склонах. Рекомендуется увеличить число итераций
   до 4-5 для сложного рельефа.

3. **Колебания параметров походки на границе Medium/Safe**:
   При traversability ≈ 0.7 возможны колебания между режимами.
   Решение: гистерезис (разные пороги для повышения и понижения).
