# Глава 3. Разработка модуля Elevation Mapping и terrain-aware планирования

## 3.12 Оценка качества и метрики

### 3.12.1 Метрики точности карты высот

Для количественной оценки качества построенной карты высот
используются стандартные метрики регрессии:

**RMSE (Root Mean Square Error):**

```
RMSE = sqrt((1/N) * Σ(z_predicted - z_ground_truth)^2)
```

RMSE чувствителен к крупным ошибкам (штрафует выбросы квадратично).
Целевое значение: < 0.05 м (5 см).

**MAE (Mean Absolute Error):**

```
MAE = (1/N) * Σ|z_predicted - z_ground_truth|
```

MAE — средняя абсолютная ошибка, менее чувствительна к выбросам.
Целевое значение: < 0.03 м (3 см).

**Max Error:**

```
Max Error = max|z_predicted - z_ground_truth|
```

Максимальное отклонение — показатель худшего случая.
Целевое значение: < 0.10 м (10 см).

**Coverage:**

```
Coverage = N_valid / N_total * 100%
```

Процент ячеек карты, для которых есть хотя бы одно измерение.
Целевое значение: > 90% после 10 секунд сканирования.

**Ground truth получение:**

Для тестовых миров Gazebo известна аналитическая функция высоты
z = f(x, y). Например:
- Для Scenario 1: z = const (0).
- Для Scenario 3: z = A * sin(ωx * x) * cos(ωy * y).
- Для Scenario 4: комбинация функций с кусочной интерполяцией.

### 3.12.2 Метрики производительности

**FPS карты (Frame Rate):**

Частота обновления elevation map на выходе ноды.
Целевое значение: ≥ 10 Гц (соответствует частоте LiDAR).

Измерение: количество сообщений `/elevation_map` за 10 секунд,
делённое на 10.

**Latency (задержка):**

Время от получения PointCloud2 до публикации обновлённой
elevation map.

```
latency = t_publish - t_receive_pointcloud
```

Целевое значение: < 100 мс.

Измерение: сравнение временных меток входящего PointCloud2
и исходящего GridMessage.

**GPU memory usage:**

Пиковое использование GPU памяти в процессе работы.
Целевое значение: < 2 GB (из 4 GB доступных на GTX 1650 Ti).

Измерение: `nvidia-smi` в процессе работы.

**CPU usage:**

Загрузка CPU в elevation контейнере (не включая GPU-вычисления).
Целевое значение: < 50%.

Измерение: `htop` или `docker stats` в процессе работы.

### 3.12.3 Метрики навигации

**Длина пути:**

Фактическая длина траектории робота от A до B.
Сравнение: baseline (без terrain-awareness) vs terrain-aware.

**Время прохождения:**

Время от старта до финиша по заданному маршруту.

**Средняя скорость:**

```
v_avg = path_length / travel_time
```

**Энергозатраты:**

Интегральная мощность приводов за время движения:

```
energy = Σ(τ_i * ω_i * Δt)
```

где τ_i — момент i-го привода, ω_i — угловая скорость i-го привода.

Измерение: из joint_states (усилие × скорость).

**Количество остановок:**

Количество экстренных остановок в no-go зонах.
В идеале: 0 (все препятствия должны быть обнаружены заранее).

### 3.12.4 Инструменты сбора метрик

Для автоматического сбора метрик разработан скрипт `compute_metrics.py`.

**Архитектура:**

```
compute_metrics.py
├── read_rosbag()
│   ├── /elevation_map
│   ├── /ground_truth (world model, Gazebo)
│   ├── /odom
│   └── /joint_states
├── compute_height_metrics()
│   ├── RMSE
│   ├── MAE
│   ├── Max Error
│   └── Coverage
├── compute_performance_metrics()
│   ├── FPS
│   ├── Latency
│   └── GPU/CPU usage
└── compute_navigation_metrics()
    ├── Path length
    ├── Travel time
    ├── Average speed
    ├── Energy consumption
    └── Stop count
```

**Формат вывода:**

Результаты сохраняются в CSV-файл:

```
scenario,rmse,mae,max_error,coverage,fps,latency,path_length,avg_speed,energy,stops
scenario_1,0.012,0.009,0.035,98.5,10.0,0.045,10.2,0.48,1250,0
scenario_2,0.015,0.011,0.042,97.2,10.0,0.048,10.5,0.42,1380,0
...
```

### 3.12.5 План сравнения с baseline

Для оценки эффективности terrain-aware подхода проводится
сравнение с baseline-режимом:

**Baseline:**
- Построение 2D costmap только на основе загруженности (occupancy).
- Фиксированные параметры походки (step_height=0.04, frequency=2.0).
- Кратчайший путь A* без учёта рельефа.

**Terrain-aware:**
- Traversability costmap с учётом рельефа.
- Адаптивные параметры походки.
- Путь выбирается с учётом безопасности.

**Ожидаемые результаты сравнения:**
- Terrain-aware: меньший RMSE карты (на 10-20%).
- Terrain-aware: меньшее количество остановок (на 50-100%).
- Terrain-aware: меньшие энергозатраты (на 15-25%).
- Baseline: меньшее время прохождения (на 10-20%), но больше рисков.
