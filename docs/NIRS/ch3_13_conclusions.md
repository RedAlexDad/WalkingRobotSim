# Глава 3. Разработка модуля Elevation Mapping и terrain-aware планирования

## 3.13 Выводы по главе

В данной главе разработан модуль Elevation Mapping и terrain-aware
планирования для шагающего робота Unitree Go2 в среде ROS 2 Jazzy
и Gazebo Harmonic.

### 3.13.1 Основные результаты

**1. Docker-интеграция:**

Разработана двухконтейнерная архитектура (CPU simulator + GPU elevation),
контейнеры общаются через Cyclone DDS с host network. Решены проблемы
совместимости CuPy/numpy, PyTorch/CUDA, RViz/Mesa. Время сборки образов
сокращено за счёт независимости контейнеров. Конфигурационные файлы
монтируются как volumes для гибкой настройки.

**2. Интеграция 3D LiDAR:**

Выбран 3D LiDAR (gpu_lidar 360×16) вместо depth-камеры из-за кругового
обзора и лучшей производительности на GPU 4GB. Написан C++ конвертер
LaserScan→PointCloudPacked для сохранения вертикальной информации.
Корректность проецирования проверена в RViz.

**3. TF relay:**

Реализован прозрачный relay для перенаправления трансформаций
с namespaced топиков (/robot1/tf) на стандартные (/tf, /tf_static)
с корректными QoS профилями (BEST_EFFORT для динамических,
TRANSIENT_LOCAL для статических трансформаций).

**4. Фильтрация облака точек:**

Настроен комплекс фильтров:
- `min_valid_distance=0.3` для исключения тела робота.
- `max_ray_length=10.0` для visibility cleanup.
- `ramped_height_range` с адаптивным порогом высоты.
- Фильтрация Махаланобиса (махалонобис_thresh=2.0).
- Visibility cleanup на CUDA для удаления динамических объектов.

**5. Elevation map:**

Карта высот публикуется с кадром odom, разрешением 0.1 м,
размером 20×20 м, с частотой 10 Гц. Содержит слои:
elevation (высота), variance (дисперсия) и traversability (проходимость).
GPU-обработка заняла < 2 мс на кадр (ускорение 10× относительно CPU).

**6. Ground segmentation:**

Реализован алгоритм Ground Plane Fitting (Zermas 2017) с 3 итерациями
RANSAC. Precision > 95%, recall > 90% на тестовых сценариях.
Ground подаётся на вход elevation_mapping, non-ground маркируется
как препятствия.

**7. Terrain-aware функции:**

Разработаны: gradient поверхности (PCA, окно 3×3), roughness (RMSE
в окне 5×5), traversability cost (взвешенная комбинация slope,
roughness, elevation difference). Классификация местности на
Safe/Medium/Unsafe с настраиваемыми порогами.

**8. Адаптация походки:**

Реализовано изменение высоты шага (0.04–0.15 м), частоты (1.0–2.0 Гц),
скорости (0.15–0.5 м/с), высоты корпуса (0.18–0.25 м) и типа походки
(trot/crawl/crawl_slow) в зависимости от traversability под опорами
робота. Переходы плавные (экспоненциальное сглаживание,
α = 0.3, время перехода 2-4 шага).

**9. Тестирование:**

Проведено тестирование на 5 сценариях (ровная дорога, неровности,
холмы, смешанный рельеф, препятствия). RMSE карты высот: 0.012–0.030 м
(цель < 0.05 м). FPS: 9.5–10.0 Гц (цель ≥ 10 Гц). Все модульные тесты
(41) пройдены.

### 3.13.3 Дальнейшие направления развития

**Краткосрочные (1-2 месяца):**

- **Подключение нейросетевой сегментации terrain**: Semantic SLAM
  для классификации типов поверхности (травa/лёд/песок/вода).
- **Интеграция с Nav2**: подключение traversability costmap как
  плагина слоя для глобального и локального planner'ов.

**Среднесрочные (3-6 месяцев):**

- **Адаптация под мультироботные системы**: разделение карты
  между несколькими роботами для коллаборативного исследования
  территории.
- **Валидация на реальном роботе Unitree Go2**: перенос модуля
  на физическую платформу с LiDAR Ouster или Velodyne.

**Долгосрочные (6+ месяцев):**

- **Обучение с подкреплением (RL)**: оптимизация параметров
  traversability и походки через RL в симуляции.
- **Предиктивная traversability**: прогнозирование изменения
  проходимости на основе истории наблюдений (например,
  размокание грунта после дождя).
- **Интеграция с манипулятором**: использование elevation map
  для планирования постановки ног на опорные точки.
