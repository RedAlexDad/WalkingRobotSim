## 1. Постановка и параметры расчёта

**Идея.** Даны девять готовых моделей; обучение не выполняется. Нужно выбрать одну для бортовой системы технического зрения и доказать выбор расчётом, а не субъективной оценкой.

**Параметры и почему они такие.**

- **T ≤ 0,1 с.** Зачем: это 10 Гц — минимальный темп контура управления. Пример: у YOLO11n T = 0,066 с, запас 34 мс. Почему допустимо: порог проверяется по аналитической оценке, то есть с запасом.
- **M ≤ 64 МБ.** Зачем: бюджет памяти борта. Пример: M = 4P для float32; 64 МБ соответствуют примерно 16 млн параметров, у YOLO11n M = 10,5 МБ. Почему допустимо: весовая память финалистов укладывается в лимит с запасом более 5 раз.
- **Π = 100 Гоп/с.** Зачем: нужна аналитическая задержка до эксперимента. Пример: натурно YOLO11n даёт 19,7 мс, аналитика — 0,066 с. Почему допустимо: оценка завышена примерно в 3,3 раза, то есть фильтр работает консервативно и не пропускает заведомо медленные модели.
- **α = 0,001 Г.** Зачем: учесть NMS и попарное сравнение рамок, растущее как N². Пример: при N = 50 добавка αN² = 2,5 Г — 38 % от F = 6,6 Г у YOLO11n. Почему допустимо: при α от 0,0005 до 0,01 порядок финалистов не меняется.
- **Сцены 5/20/50.** Зачем: низкая, средняя и высокая плотность объектов. Почему допустимо: худший случай (50 объектов) входит в проверку, вероятности сцен не требуются.

## 3. Характеристики модели

**Идея.** Пять основных характеристик описывают разные стороны пригодности: стоимость вычислений, сложность, ёмкость, однозначность и наглядность. Каждая — число с формулой и единицами, без экспертного балла.

### 3.1. Эффективность E

- **Идея.** Сколько вычислений требуется на кадр.
- **Формула.** E = 1/F; единицы 1/Г.
- **Пример.** YOLO11n: 1/6,6 = 0,152; YOLOv8n: 1/8,9 = 0,112; CNN+LSTM: 1/6,61 = 0,151.
- **Зачем (практика).** Сравнивать вычислительную стоимость независимо от платформы; задержка учитывается отдельно через T.
- **Почему допустимо.** E — монотонное преобразование F, информация не теряется; абсолютного порога нет, значение используется только для сравнения.

### 3.2. Читаемость C

- **Идея.** Насколько проста структура модели для анализа и сопровождения.
- **Формула.** C = τ / log₂(P + 1), где P — абсолютное число параметров; τ = 1 для CNN, 0,5 для transformer; единицы безразмерные.
- **Пример.** P = 2,62·10⁶: log₂(P + 1) = 21,32, C = 0,047; P = 3,16·10⁶: C = 0,046; P = 3,15·10⁶: C = 0,046.
- **Зачем (практика).** Число параметров различается на порядки; логарифм сжимает диапазон, τ учитывает разную сложность архитектур.
- **Почему допустимо.** Абсолютного порога нет; у финалистов C практически одинакова, поэтому она работает как tie-breaker, а не как решающий фактор.

### 3.3. Различимость R

- **Идея.** Ёмкость модели, то есть способность разделять классы.
- **Формула.** R ≈ VCdim ≈ W·L·log W, где W — число весов, L — глубина; единицы — число областей.
- **Пример.** VCdim = 10,1·10⁹ у YOLO11n, 8,8·10⁹ у YOLOv8n, 12,3·10⁹ у CNN+LSTM.
- **Зачем (практика).** Архитектурная оценка не требует датасета и позволяет сравнивать модели до эксперимента; выше R — больше ёмкость.
- **Почему допустимо.** Абсолютное значение не интерпретируется как точность; при одной формуле сравнивается только порядок моделей. CNN+LSTM имеет большую ёмкость, но проигрывает по стоимости.

### 3.4. Однозначность O

- **Идея.** Насколько однозначно модель выбирает класс объекта.
- **Формула.** O = 1 для softmax + argmax; O = 1/k для мультиметки; безразмерная.
- **Пример.** У всех трёх финалистов O = 1.
- **Зачем (практика).** Фиксирует тип выхода: один класс на объект или несколько.
- **Почему допустимо.** O одинакова у финалистов и не различает их; в Φ не входит, но нужна для описания выхода.

### 3.5. Наглядность H

- **Идея.** Насколько просто оператору интерпретировать выход.
- **Формула.** H = 1 / log₂(k + 1), где k — число одновременно выводимых сущностей; для k = 80 H = 0,157.
- **Пример.** У всех трёх финалистов H = 0,157.
- **Зачем (практика).** Оценивает сложность восприятия выхода, а не точность модели.
- **Почему допустимо.** H одинакова у финалистов и не различает их; в Φ не входит, как и O.

### 3.6. Ресурсные характеристики

- **Идея.** P, F, M, T, f, Q прямо ограничивают работу на борту; L и P/L — архитектурные признаки сложности.
- **Формулы.** P — параметры, млн; F — FLOPs, Г; M = 4P — память float32, МБ; T — базовая задержка, с (T = F/Π, кроме CNN+LSTM); f = 1/T — частота, Гц; Q = 10·T — энергия кадра при 10 Вт, Дж; L — число слоёв; P/L — параметров на слой.
- **Пример.** P = 2,62/3,16/3,15 млн; F = 6,6/8,9/6,61 Г; M = 10,5/12,6/12,6 МБ; T = 0,066/0,089/0,070 с; f = 15,2/11,2/14,3 Гц.
- **Зачем (практика).** Это жёсткие ограничения борта и входные данные для Φ.
- **Почему допустимо.** У всех T < 0,1 с и M < 64 МБ; ресурсные значения измеряемы или выводятся из спецификации.

## 4. Сведение характеристик и Φ

- **Идея.** Получить одно число для сравнения моделей без субъективных весов.
- **Формула.** z = (x − min)/(max − min) для «больше — лучше»; z = (max − x)/(max − min) для «меньше — лучше»; Φ = (1/K)Σz.
- **Пример.** Для T: min = 0,066, max = 0,089; z(YOLO11n) = 1, z(YOLOv8n) = 0, z(CNN+LSTM) = 0,83. Суммы: 9,63/2,00/5,32; Φ = 0,875/0,182/0,484.
- **Зачем (практика).** Свернуть 11 признаков в один показатель и проверить, что выбор не держится на одной характеристике.
- **Почему допустимо.** Веса равны 1/K, Парето не используется; O и H исключены как константы. Φ не имеет абсолютной шкалы, значим только порядок; разрыв YOLO11n и CNN+LSTM — 0,391. Проверка без связанных признаков (E, P/L) сохраняет порядок.

В Φ входят 11 признаков: P, F, M, T, f, E, Q, L, P/L, VCdim, C. Направления: P, F, M, T, Q, L, P/L, VCdim — «меньше — лучше»; f, E, C — «больше — лучше».

## 5. Критерии и доказательство выбора

- **Идея.** Сцена заранее неизвестна; сравнить модели в трёх состояниях без вероятностей сцен.
- **Формула.** f(i,j) = 1 / (T(i) + α·N(j)²/Π), где T(i) — базовая задержка, α·N(j)² — стоимость постобработки в гигаоперациях, деление на Π переводит её в секунды.
- **Пример.** YOLO11n, N = 5: f = 1/(0,066 + 0,001·25/100) = 15,09 Гц; при N = 20 и 50 — 14,29 и 10,99 Гц.
- **Зачем (практика).** Учесть деградацию в плотной сцене, которую фильтр по базовой T не видит.

**Таблица 3.** Частоты и результаты пяти критериев

| Модель | f(5) | f(20) | f(50) | Лаплас | Оптимизм | Вальд | Сэвидж | Гурвиц |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| YOLO11n | 15,09 | 14,29 | 10,99 | 13,46 | 15,09 | 10,99 | 0,00 | 13,04 |
| YOLOv8n | 11,20 | 10,75 | 8,77 | 10,24 | 11,20 | 8,77 | 3,89 | 9,99 |
| CNN+LSTM | 14,23 | 13,51 | 10,53 | 12,76 | 14,23 | 10,53 | 0,86 | 12,38 |

### 5.1. Пять критериев

- **Лаплас.** Идея: сцены равновероятны. Формула: среднее по сценам. Пример: 13,46/10,24/12,76. Зачем: нейтральная оценка без оптимизма и пессимизма.
- **Оптимизм.** Идея: лучший сценарий. Формула: максимум. Пример: 15,09/11,20/14,23. Зачем: верхняя граница, полезная для проверки запаса.
- **Вальд.** Идея: гарантия в худшем случае. Формула: максимум минимума. Пример: 10,99/8,77/10,53. Зачем: не даёт выбрать модель, которая разваливается при 50 объектах.
- **Сэвидж.** Идея: минимум сожаления. Формула: min по i от max по j разности «лучший в сцене минус результат модели». Пример: 0/3,89/0,86. Зачем: показывает цену ошибки относительно лучшего выбора в каждой сцене.
- **Гурвиц.** Идея: компромисс между лучшим и худшим. Формула: 0,5·max + 0,5·min. Пример: 13,04/9,99/12,38. Зачем: не быть ни крайним оптимистом, ни крайним пессимистом.

### 5.2. Доказательство

YOLO11n лучшая во всех трёх сценах, поэтому её сожаление по Сэвиджу равно 0; все пять критериев дают её же. В худшей сцене она держит 10,99 Гц > 10 Гц. У YOLOv8n только 8,77 Гц — ниже порога, несмотря на формальный проход по T = 0,089 с. CNN+LSTM держит 10,53 Гц, но уступает по Лапласу (12,76 против 13,46) и Гурвицу (12,38 против 13,04); преимущество YOLO11n по Вальду — 0,46 Гц (4,4 %). Фильтр по T проверяет только базовую задержку; критерии учитывают деградацию в плотной сцене, поэтому одного фильтра недостаточно.

### 5.3. Проверка 22 способами

- **Идея.** Проверить, что результат не зависит от одной свёртки или одного критерия.
- **Пример.** 21 из 22 способов ставит YOLO11n на первое место. Исключение — SR, метрика масштаба семейства, не оценивающая пригодность конкретной модели.
- **Практика.** Ψ = 0,955/0,735/0,045; число Борда 64/42/23; средний ранг 1,045/2,000/2,909. Совпадение критериев, Φ и 21 из 22 способов делает вывод устойчивым.

## 6. Экспериментальная проверка

- **Идея.** Эксперимент — подтверждение расчёта, а не основание выбора; сравнение относительное, на одной разметке.
- **Пример.** 4 синтетические сцены (340 объектов), кафе (66), COCO128 (929).

**Таблица 4.** mAP@0,5 по доменам

| Домен | YOLO11n | YOLOv8s | YOLOv8n |
|---|---:|---:|---:|
| 4 синтетические сцены, mAP@0,5 | 0,475 | 0,406 | 0,376 |
| Кафе, mAP@0,5 | 0,402 | 0,435 | 0,478 |
| COCO128, mAP@0,5 | 0,671 | 0,761 | 0,607 |

- **Практика.** На целевых сценах YOLO11n лучшая: 0,475 против 0,406 и 0,376. В кафе лучшая YOLOv8n (0,478), на COCO128 — YOLOv8s (0,761): это доменная зависимость, а не ошибка расчёта.
- **Почему допустимо.** Абсолютный mAP ограничен малой разметкой; для выбора используется порядок, а не абсолютный порог. Задержка YOLO11n — 19,7 мс, YOLOv8s — 51 мс; аналитическая оценка YOLOv8s 0,288 с в 5,6 раза выше измеренной, то есть фильтр консервативен. По натурному замеру YOLOv8s укладывается в 0,1 с; при менее жёстком бюджете она могла бы конкурировать по точности.

## 7. Ограничения

- **Что ограничивает.** VCdim, C и Q — расчётные оценки; mAP в таблице кандидатов — точность предобученных моделей на COCO, а не после дообучения. Эксперимент покрывает YOLO-модели; RT-DETR-l, Faster R-CNN и CNN+LSTM проверены только аналитически. Выборки малы: 340/66/929 объектов.
- **Почему вывод сохраняется.** Жёсткие T и M проверены с запасом, а 21 из 22 способов и все пять критериев дают одну модель; ограничения меняют область применимости, но не порядок финалистов. При изменении Π, разрешения или числа классов расчёт нужно повторить.

## 8. Заключение

При заданных ограничениях выбрана YOLO11n: P = 2,62 млн, F = 6,6 Г, M = 10,48 МБ, T = 0,066 с, f = 15,15 Гц, Φ = 0,875, Ψ = 0,955, Борда 64, ранг 1,045. Она первая по всем пяти критериям и в 21 из 22 способов, в худшей сцене держит 10,99 Гц. Результат действителен для целевых синтетических сцен и указанных порогов; на других доменах возможны другие победители.
