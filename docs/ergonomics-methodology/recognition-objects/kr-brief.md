# Памятка по теме КР (справка)

**Тема:** Эргономическое обоснование представления результатов
распознавания объектов оператору мобильного робота
**Дисциплина:** ЭА_СОиОИ
**Контекст:** консультация 06.10.2026 (расчёт цепочки, без экспертов)
**План работ и ответы на вопросы:** см. `kr-plan.md`

---

## 1. Что требует преподаватель

- **Эргономическое обоснование = доказательство** того, что выбранное
  представление обеспечивает нужное качество деятельности, с указанием
  **основания**.
- **Считать информационную цепочку по модели**: где и сколько теряется
  на каждом звене.
- **Экспертиза и фокус-группы исключены** («это не наука»).
- **Эксперимент — только проверка** (практика), а не основание.
- Порядок: **сначала теория/модель, потом проверка**.
- Три объекта анализа: **процесс / деятельность оператора / аварийные
  сигналы и их представление**.
- Задача может быть **частью цепочки**, но анализ — обязателен.

## 2. Вектор анализа

**Вектор:** информационно-перцептивный — как результат распознавания
доходит до оператора и влияет на его решение.

| Что            | Значение                                                      |
| -------------- | ------------------------------------------------------------- |
| Вектор         | представление результата распознавания → восприятие оператора |
| Узкий выбор    | звено «экран → оператор» в цепочке распознавания              |
| На что смотрим | точность на звеньях и её потери                               |
| Что считаем    | потери по звеньям, вклад, итоговую точность                   |
| Что НЕ смотрим | обучение модели, mAP (техника детектора)                      |

**Тема:** «Эргономическое обоснование представления результатов
распознавания объектов оператору мобильного робота».

## 4. Информационная цепочка (5 звеньев)

```mermaid
graph LR
    F["Кадр<br/>(сенсор)"] --> C["Захват"]
    C --> D["Детектор<br/>(класс, уверенность)"]
    D --> P["Представление<br/>(экран)"]
    P --> O["Оператор<br/>(восприятие)"]
    O --> R["Решение"]
```

Ключевая мысль: детектор — источник данных; эргономика — на звене
**представление → оператор**. Но её вклад виден только в **общем расчёте**
цепочки.

### 4.1. Звенья и их показатели

| Звено         | Коэф. | Показатель               | Возможные потери              |
| ------------- | ----- | ------------------------ | ----------------------------- |
| Захват        | $a_1$ | доля потерянных объектов | шум, смаз, частота            |
| Детектор      | $a_2$ | precision/recall/F1      | пропуски, ложные              |
| Представление | $a_3$ | ECE + различимость       | незаметность, неоднозначность |
| Оператор      | $a_4$ | $d'$, время, нагрузка    | ошибки считывания             |
| Решение       | $a_5$ | верное решение           | неверное доверие              |

## 5. Ядро модели (кратко)

Итоговая точность цепочки:

$$A = \prod_{i=1}^{n} a_i$$

Вклад звена в потерю:

$$\ell_i = \frac{1 - a_i}{\sum_j (1 - a_j)}$$

Полный разбор (ECE, SDT, числовой пример) и набор метрик — в
`kr-plan.md`.

### 6.2. Характеристики (качества модели)

| Характеристика          | Что означает                  | Приоритет |
| ----------------------- | ----------------------------- | --------- |
| Однозначность класса    | класс читается верно          | высокий   |

| Различимость объектов   | метки не сливаются            | средний   |
| Нагрузка на внимание    | минимум одновременно          | средний   |
| Цветовая различимость   | классы различаются цветом     | средний   |

## 7. Пример: кадр и расчёт

| №   | Класс    | Уверенность | Позиция                   |
| --- | -------- | ----------- | ------------------------- |
| 1   | person   | 0.92        | центр                     |
| 2   | chair    | 0.71        | слева                     |
| 3   | bottle   | 0.55        | внизу                     |
| 4   | (bottle) | 0.48        | ниже порога → не показано |

Проблема: если 0.55 показать как 0.92 — оператор **доверяет ошибочно**.
Значит, уверенность нужно выразить явно (цвет/значок), и это повышает
$a_3$ в модели.

**Ключевая мысль:** распознавание полезно, если оператор верно им

| ------------------- | ---------------------- | --------- |
| Заметил метку       | увидел объект          | критичный |

| Характеристика     | Метрика                   | Пример  |

## 9. Математические основания и источники

Модели, на которые опирается работа (цепочка и вклады — см. §5 и
`kr-plan.md`):

| Модель      | Формула                                                                         | Что даёт                 |
| ----------- | ------------------------------------------------------------------------------- | ------------------------ |
| SDT         | $d' = z(H)-z(F)$                                                                | ошибки детекции          |
| ECE         | $\sum_m \tfrac{\lvert B_m \rvert}{n}\,\lvert \mathrm{acc}-\mathrm{conf} \rvert$ | калибровка уверенности   |
| Хик–Хайман  | $RT = a + b\log_2(n+1)$                                                         | нагрузка/число вариантов |
| Фиттс       | $MT = a + b\log_2(A/W+1)$                                                       | наведение/размер метки   |
| Вебер       | $\Delta I/I = k$                                                                | различимость             |
| CIE         | $\Delta E_{00}$                                                                 | цвет                     |
| AoI         | $\Delta(t) = t - u(t)$                                                          | свежесть                 |

Источники: Shannon 1948; Hick 1952; Fitts 1954; Green & Swets 1966;
Miller 1956; Endsley 1995; Lee & See 2004; Guo 2017; стандарты
ГОСТ Р ИСО 9241, MIL-STD-1472, WCAG 2.1.
