# Алгоритм объективного выбора модели МО (без весов и без Парето)

**Тема:** Обоснование выбора модели машинного обучения для распознавания
объектов оператору мобильного робота
**Дата:** 2026-10-13
**Связанные документы:** `mmo-decomposition.md`, `model-choice.md`
**Статус:** черновик к согласованию

Принцип: **никаких весовых коэффициентов и никакого критерия Парето**.
Только **объективные величины, извлекаемые из самой модели** (её данных),
и **собственный детерминированный алгоритм**.

---

## 1. Какие данные берём из модели (объективно)

Из модели извлекаются только её **собственные данные** (без обучения и без
прогонов на датасете):

| Данные модели | Обозн. | Откуда |
| --- | --- | --- |
| Число параметров | $P$ | спецификация/архитектура |
| Вычислительная стоимость | $F$ (FLOPs) | архитектура |
| Число классов | $k$ | выход модели |
| Тип выхода | — | рамка/маска |
| Глубина | $L$ | архитектура |

Из них считаются производные величины:

$$M = 4P\ \text{(fp32)}\ \text{или}\ 2P\ \text{(fp16)},\qquad
T = \frac{F}{\Pi},\qquad E=\frac{1}{F},\qquad
O=\frac{1}{k},\qquad H=\frac{1}{\log_2(k+1)}$$

где $\Pi$ — производительность вычислителя робота (оп./с).

---

## 2. Собственный алгоритм выбора

### Шаг 1. Жёсткие требования задачи (отсев, без весов)

Задаются из требований робота (не «важность», а **допуски**):

- реальное время: $T \le T_{\max}$ (например, не медленнее $f_{\min}$ Гц);
- бортовая память: $M \le M_{\max}$;
- обязательные возможности: наличие **маски** (если нужна) и т.п.

Модели, не прошедшие, **исключаются** (не «штрафуются»).

### Шаг 2. Объективное ранжирование оставшихся

По каждой характеристике модели **ранжируются** (1 — лучшая) строго по
числу. Ранжирование **не содержит весов** — оно опирается только на
порядок значений.

Суммарный показатель:

$$S = \sum_{c} \operatorname{rank}_c, \qquad \text{лучшая} = \arg\min S$$

(метод суммы рангов: объективно и без весов).

### Шаг 3. Правило разрешения ничьей

При равенстве $S$ — сравнение по характеристике из **жёсткого требования**
(например, меньше $T$, затем меньше $M$, затем меньше $P$).

**Итог:** выбор детерминирован и воспроизводим: те же данные → та же
модель.

## 5. Применение алгоритма

### Шаг 1. Жёсткие требования

- реальное время: $f \ge 10$ Гц ($T \le 0.1$ с);
- бортовая память: $M \le 64$ МБ.

| Модель | $f \ge 10$ Гц | $M \le 64$ МБ | Прошла |
| --- | --- | --- | --- |
| YOLOv8n | да | да | **да** |
| YOLOv11n | да | да | **да** |
| YOLOv8s | нет | да | нет |
| YOLOv11s | нет | да | нет |
| RT-DETR-l | нет | нет | нет |

Допустимые: **YOLOv8n, YOLOv11n**.

### Шаг 2. Ранжирование допустимых

Ранги (1 — лучше) по характеристикам (меньше — лучше, кроме $E$, $f$):

| Модель | rank($P$) | rank($F$) | rank($M$) | rank($T$) | rank($E$) | Сумма $S$ |
| --- | --- | --- | --- | --- | --- | --- |
| YOLOv8n | 2 | 2 | 2 | 2 | 2 | **10** |
| YOLOv11n | 1 | 1 | 1 | 1 | 1 | **5** |

### Результат

**YOLOv11n** — минимальная сумма рангов (5 против 10) и лучше по всем
объективным характеристикам одновременно.

---

## 6. Почему алгоритм корректен для требований

1. **Нет весов** — ранги опираются только на порядок чисел.
2. **Нет Парето** — используется собственная детерминированная процедура
   (отсев → сумма рангов → ничья).
3. **Только объективные данные модели** — $P$, $F$, $k$, тип выхода; всё
   выводится из архитектуры.
4. **Воспроизводимо** — одинаковые данные дают одинаковый выбор.

---

## 7. Обобщение алгоритма

Для любого набора моделей и задачи:

1. извлечь из моделей $P$, $F$, $k$, тип выхода → посчитать $M$, $T$, $E$,
   $O$, $H$;
2. отсеять по **жёстким требованиям** задачи;
3. ранжировать оставшиеся по каждой характеристике (1 — лучшая);
4. выбрать модель с **минимальной суммой рангов**;
5. ничью решить по характеристике из жёсткого требования.

---

## 8. Открытые вопросы к преподавателю

1. Подтвердить **жёсткие требования** (частота, память) для робота.
2. Согласовать набор характеристик для ранжирования.
3. Проверить спецификации моделей (вход, $P$, FLOPs).
4. Нужна ли **маска** (тогда добавляются сегментаторы).
