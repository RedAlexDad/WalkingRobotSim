объектов оператору мобильного робота

**Связанные документы:** `mmo-decomposition.md`, `model-comparison-math.md`

## 3. Применение алгоритма ко всем характеристикам

### Шаг 1. Отсев (тип «О»)

Пределы: $T\le0.1$ с ($f\ge10$ Гц), $M\le64$ МБ, тип выхода — рамка,
детерминизм — да, квантуемость — да.

### Шаг 3. Результат

**Выбор: YOLO11n** — минимальная сумма рангов (11 против 15). Проигрывает
только по числу слоёв $L$ (181 против 129), но выигрывает по параметрам,
FLOPs, памяти, задержке, частоте, энергии и читаемости.

---

## 4. Почему используются все характеристики

1. **Отсев** — характеристики с жёстким пределом ($T$, $M$, тип выхода,
   детерминизм, квантуемость): модель с неподходящим значением
   **исключается**.
2. **Ранжирование** — все остальные числовые характеристики: каждая даёт
   ранг, суммирование объективно (без весов).
3. **Нейтральные (=)** — одинаковые у всех, на выбор не влияют, но
   показывают, что задача для них эквивалентна.

Так каждая из ~63 характеристик либо отсеивает, либо ранжирует.

---

## 5. Обобщение алгоритма

1. Заполнить матрицу «модель × характеристика» (из спецификаций).
2. Пометить каждую характеристику: **отсев** / **ранг** / нейтральна.
3. Отсеять по «отсев»-характеристикам.
4. Ранжировать оставшиеся по всем «ранг»-характеристикам.
5. Выбрать модель с минимальной суммой рангов.
