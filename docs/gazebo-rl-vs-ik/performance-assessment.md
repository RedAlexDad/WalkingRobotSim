# Оценка производительности симуляции и GPU (gz-sim)

**Дата:** 2026-10-09
**Вопрос:** потянет ли стенд GPU-ускоренную симуляцию для корректных
замеров RL-походки?

---

## 1. Железо и окружение

| Компонент | Значение |
|---|---|
| GPU | **NVIDIA RTX 5070 Ti** (eGPU, PCI 01:00.0), драйвер 595.91.07, CUDA 13.2 |
| iGPU | AMD HawkPoint1 (PCI 6f:00.0) |
| nvidia-container-toolkit | **есть** (`nvidia-ctk`, docker runtime `nvidia`, CDI `nvidia.com/gpu=all`) |
| Контейнер `walking_robot_sim` (как запущен) | **без GPU**: нет `/dev/dri`, нет `nvidia-smi`, `torch.cuda.is_available()=False` |
| Проброс GPU | `compose.nvidia.yml` (runtime nvidia) или `compose.gpu.yml` (AMD), подключаются через `WRS_GPU` |

## 2. Ключевой факт

**Физика `gz-sim` считается на CPU (движок DART).** GPU в gz-sim
используется только для **рендеринга/сенсоров** (камера, лидары, GUI), но
**не для физики**. Поэтому «GPU-ускорение Gazebo» в смысле быстрой физики
**недоступно**.

## 3. Замеры real-time factor (RTF)

RTF = отношение модельного времени к реальному (1.0 = реальное время).
Получено из `gz topic -e -t /world/default/stats` (`real_time_factor`).

| Сценарий | RTF (наблюдения) | Вывод |
|---|---|---|
| Полный стек (Gazebo + Go2 + датчики + Nav2/SLAM + мосты) | **0.07 … 0.37** (в основном ~0.1) | симуляция идёт ~в 10 раз медленнее реального времени |
| Только мир `cafe.world` (без робота/Nav2) | **0.24 … 0.56** | даже «пустой» мир ~в 2–4 раза медленнее |
| Только мир `terrain_test.world` (без робота/Nav2) | **0.11 … 0.40** | то же |

**Вывод:** узкое место — **CPU-физика gz-sim** (и сложность мира), а не GPU.

## 4. Что реально влияет на RTF

1. **Загрузка CPU** тяжёлым стеком: Nav2 (~15 нод), SLAM, RViz,
   `ros_gz_bridge`, image bridge.
2. **Сенсоры робота** в URDF: камера, depth-камера, 3D-лидар —
   рендерятся даже headless (software rendering) и грузят CPU.
3. **Сложность мира** (число моделей/коллизий).
4. **Шаг физики**: `max_step_size` (сейчас 0.005 с) и число итераций
   решателя.

## 5. Варианты

### 5.1. GPU-проброс (не решит проблему RTF)
Проброс NVIDIA/AMD в контейнер возможен (`compose.nvidia.yml` /
`compose.gpu.yml`), но даёт ускорение только **рендеринга/GUI/сенсоров**,
а **не физики**. Для headless RL-замеров RTF это не поднимет.

### 5.2. «Минимальная сцена» (рекомендуется)
Запускать **только мир + робот + контроллеры**, без Nav2/SLAM/RViz, при
необходимости отключить камеру/лидар; простой мир (плоскость); при
необходимости увеличить `max_step_size`. Это должно поднять RTF
существенно (цель ≥ 0.5–1.0). Проверяется тем же
`/world/default/stats`.

### 5.3. Настоящая GPU-физика (за рамками Gazebo)
Если нужна быстрая физика — её дают **Isaac Sim / Genesis / MuJoCo**
(GPU/ускоренные), но это другие симуляторы (по условию задачи не
рассматриваем; Isaac/MuJoCo уже отмечены как источники политики).

## 6. Итог

- **GPU-ускорить физику Gazebo нельзя** (CPU DART). Текущий стенд
  способен только на CPU-симуляцию с **RTF ≈ 0.1** в полном стеке.
- Для корректных замеров ходьбы нужен **минимальный сценарий** (5.2), а
  не GPU.
- Включение GPU в контейнере имеет смысл только для GUI/сенсорного
  рендеринга.

### Рекомендация

1. Собрать **минимальный launch** (мир + Go2 + `joint_state_broadcaster` +
   `joint_group_effort_controller`, без Nav2/RViz; опционально без
   камеры/лидара).
2. Замерить RTF по `/world/default/stats`; настроить `max_step_size`.
3. Тогда прогонять серии RL vs IK с приемлемым темпом.
