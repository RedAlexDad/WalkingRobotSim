## 6. Протокол эксперимента (единый для обоих контроллеров)

Чтобы сравнение было корректным, **оба** контроллера запускаются в
идентичных условиях:

- робот: Unitree Go2 (ассет IsaacLab `go2.usd`);
- среда: Isaac Sim 6.0.1 / IsaacLab 3.0;
- поверхность: плоская, трение 1.0;
- команда: vx = 0.3 м/с, vy = 0, wz = 0;
- длительность: не менее 10 с (2000 шагов), лучше 20–30 с;
- старт: STANDING;
- повторов: не менее 3 прогонов на контроллер (для среднего/std);
- фиксировать: X,Y,Z, roll/pitch/yaw, q, qdot, команды суставов,
  время шага/частоту.

**Метрики:** средняя скорость, пройденное расстояние, Std(Z), дрейф |Y|,
max|roll|, max|pitch|, время до устойчивой походки, CoT, число шагов до
сбоя.

**Примечание:** сравнение при «родных» PD каждого режима (25 vs 75);
опционально — серия с выровненными PD.

## 7. План сбора данных (по шагам)

1. **Телеметрия.** ✅ Реализовано:
   - `src/isaac/telemetry.py` — логгер CSV (корпус, углы, суставы, команды);
   - `src/isaac/run_sim_telemetry.py` — лаунчер IsaacLab с записью;
   - `src/isaac/run_isaaclab.sh` — теперь запускает лаунчер с телеметрией;
   - `src/isaac/analyze_telemetry.py` — расчёт метрик и графиков из CSV.
2. **Серия IK/TROT.** 3 прогона по 20–30 с, сохранить CSV.
3. **Серия RL.** 3 прогона с командой vx=0.3, сохранить CSV.
4. **Обработка.** `analyze_telemetry.py` → метрики (скорость, Z, std,
   дрейф, углы, CoT).
5. **Возмущения.** Толчок сбоку, скользкая поверхность — качественно +
   численно, если реализуемо.
6. **Иллюстрации.** Скриншоты GUI, графики X(t)/Y(t)/Z(t)/углы.
7. **Сведение.** Заполнить таблицы 1–2 черновика, убрать ⚠️-заглушки.

### 7.1. Как запускать телеметрию

```bash
# серия IK/TROT (наш Rust-контроллер)
GO2_TELEMETRY_TAG=ik bash src/isaac/run_isaaclab.sh --headless

# серия RL (политика NVIDIA) — тег rl
GO2_TELEMETRY_TAG=rl bash src/isaac/run_isaaclab.sh --headless

# разбор записанных CSV
python3 src/isaac/analyze_telemetry.py logs/isaac/telemetry_ik_*.csv \
        logs/isaac/telemetry_rl_*.csv --json logs/isaac/summary.json --plot
```

Переменные окружения:
- `GO2_TELEMETRY=0` — отключить запись;
- `GO2_TELEMETRY_TAG=ik|rl` — метка в имени файла;
- `GO2_TELEMETRY_CSV=/path.csv` — явный путь к файлу.

### 2026-09-13 — усиление логирования и IMU-моста

Реализовано в `run_sim_telemetry.py` / `run_isaaclab.sh`:

1. **Время шага.** `timeline.get_current_time()` застревает (1.10) →
   время считается как `step * physics_dt` (0.005).
2. **IMU-мост.** Публикация `/robot1/imu` (`sensor_msgs/Imu`) из obs
   (ориентация, угловые скорости, ускорения) — контроллер использует
   ориентацию для компенсации крена/тангажа.
3. **Type support.** В `LD_LIBRARY_PATH` добавлен `${ISAAC_JAZZY}/lib`
   — без него rclpy Isaac Sim не грузит `geometry_msgs`/`sensor_msgs`.
4. **Структурированный лог:** `[SIM] REPORT` раз в 50 шагов (поза, rpy,
   `joint_err` max/mean, fps, статус IMU), детекция NaN/Inf, лог смены
   команды `CMD CHANGE`.

**Результат первого прогона (IK/TROT, vx=0.3):** робот устойчиво стоит
в REST, но при переходе в **TROT падает за ~1–2 с**:
`z_std=0.137`, `max_roll=59°`, `max_pitch=54°`, дрейф по Y=0.73 м,
`joint_err` до 1.4 рад. Гипотеза: TrotGait тюнен под Gazebo; большие
амплитуды + разные PD (25 vs 75) → потеря устойчивости на ассете NVIDIA.
Результат «18 400 шагов» из отчёта v10.0 в текущей сборке не
воспроизводится — требуется отдельная отладка контроллера.

### 2026-09-13 — исправление дрейфа стопы в TrotGait

**Диагноз (численная модель походки, порт в Python):** в
`TrotStanceController::position_delta` скорость стопы считалась как
`-(step_dist/4)/(dt*stance_ticks)`. Делитель `stance_ticks` — длина
ОДНОЙ stance-фазы (9 тиков), тогда как в трот-расписании нога стоит на
земле 3 фазы подряд (27 тиков). Стопа уезжала назад втрое дальше, чем
возвращал swing (`foot_x` до −1.2 м), IK уходил в насыщение (`calf=0`,
нога полностью выпрямлена), робот падал.

**Исправление:** физически корректная скорость стопы в системе тела —
`velocity = -cmd_vel` (стопа фиксирована в мире), плюс прежняя
z-компенсация. Проверено численной моделью: `loc_z` ограничен, `calf`
в диапазоне −82…−104° (без насыщения). Изменены
`quadropted-core/src/controllers/trot/stance.rs` и тест; 2
кросс-валидационных теста с C++ помечены `#[ignore]` (намеренное
отклонение). Все остальные тесты ядра проходят.

**Результат в Isaac Sim (vx=0.3):** робот теперь **идёт вертикально**
(Z≈0.256 м) от x≈0.28 до x≈0.9 м, `joint_err` 0.05–0.2 (было 1.4),
NaN нет. Затем падает из-за **бокового дрейфа** (Y растёт 0.02→0.65,
roll −8°→−54°) — это ранее известная проблема 28 отчёта
(нестабильное направление/курс). Следующий шаг: стабилизация курса/крена.
