## 1. Один ассет для обоих контроллеров (убирает главный контраргумент)

**Проблема:** IK работает на IsaacLab `go2.usd`, RL (`go2_policy.py`) — на
Mujoco_Menagerie `go2.usda`, PD 75 vs 25. Рецензент может сказать, что
различия — от ассета/гейнов, а не от парадигмы.

**Вариант A (предпочтительный): запустить RL-политику внутри IsaacLab.**
1. В `run_sim_telemetry.py` добавить режим `GO2_CONTROLLER=rl`: загрузить
   `physx_policy.pt` (`torch.jit.load`) и `physx_env.yaml`.
2. Сформировать 48-мерное наблюдение из obs IsaacLab-среды (lin/ang vel в
   теле, гравитация, команда, ошибка суставов, скорости, прошлое действие).
3. Переупорядочить суставы: политика ждёт FL,FR,RL,RR × (hip,thigh,calf),
   IsaacLab — FR,FL,RR,RL × (hip,thigh,calf).
4. `target = default_pos + action * action_scale`; применять через
   `env.action` (тот же интерфейс, что у IK).
5. Прогнать 3 повтора на **том же `go2.usd`** и снять телеметрию.

**Вариант B:** запустить IK на Menagerie-ассете (в `go2_policy.py`-стиле) —
проще по обвязке, но теряется IsaacLab.

**Критерий:** обе серии на одном USD, одинаковые PD → сравнение корректно.

## 2. Возмущения (толчок) — механизм готов

Механизм реализован: топик `/robot1/push` (`std_msgs/Float64`, Н, ось Y),
применяется `GO2_PUSH_DUR` секунд через `set_external_force_and_torque`.

**Протокол:**
1. Серия IK: старт, TROT (vx=0.3), через 3 с — толчок **30/60/90 Н**.
2. Серия RL: то же (для RL нужен аналогичный хук в `go2_policy.py`).
3. Метрики: факт падения, время восстановления, max крен после толчка.
4. Пороговая матрица (сила × контроллер).

**Ожидание:** RL восстанавливается после большего толчка; IK падает раньше.
Усиливает тезис «IK — резервный режим».

## 3. fps-свип (количественно подтверждает P1)

Механизм готов: `GO2_TARGET_FPS` (троттлинг wall-fps).

**Ключевой момент:** текущий контроллер — **сим-временной** →
fps-инвариантен (свип покажет одинаковый результат — это доказательство
исправления). Чтобы показать **эффект** привязки, нужен **wall-clock
вариант** контроллера (старый цикл).

**Протокол:**
1. Собрать два варианта: `sim-time` (текущий) и `wall-clock`
   (флаг `GO2_WALLCLOCK` → цикл на `SystemTime`/`sleep(16ms)`).
2. Прогнать каждый при **30 / 60 / 120 / 240 fps** (`GO2_TARGET_FPS`).
3. Построить график «метрика (дрейф/крен/пройдено) vs fps».
4. Ожидание: wall-clock — сильная зависимость; sim-time — плоская.

**Результат:** количественное доказательство P1 (сильнейший вклад статьи).
