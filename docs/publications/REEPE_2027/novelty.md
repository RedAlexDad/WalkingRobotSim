# Научная новизна — REEPE-2027 (IEEE / Scopus)

**Дата:** 2026-10-15
**Статья:** «Сравнение обученной политики и модельного IK/TROT-контроллера
для походки четвероногого робота (Unitree Go2) в Isaac Sim»
**Секция:** Computing, Signal Processing, and Analysis
**Связано:** `../scientific-novelty.md`, `plan-reepe-2027.md`.

---

## 1. Состояние вопроса (по литературе)

**Доминирует обучение с подкреплением (RL).** Классика и свежие работы
строят именно RL-политики для квадруped-локомоции:

- Sim-to-Real: Learning Agile Locomotion For Quadruped Robots (RSS 2018,
  DOI 10.15607/rss.2018.xiv.010);
- Hierarchical RL for Quadruped Locomotion (IROS 2019,
  10.1109/iros40897.2019.8967913);
- DreamWaQ (ICRA 2023, 10.1109/icra48891.2023.10161144);
- Learning Torque Control for Quadrupedal Locomotion (Humanoids 2023,
  10.1109/humanoids57100.2023.10375154);
- Isaac Sim-to-Real: RL-based Locomotion for Quadrupeds (2025,
  10.1109/case58245.2025.11163761);
- Towards Torque-Driven RL for Quadruped Locomotion (SII 2026,
  10.1109/sii64115.2026.11404550).

**Тренд — гибриды RL + модельное управление** (то есть модельный
контроллер берут как «часть» системы, а не как объект сравнения):

- RAMBO (arXiv:2504.06662) — RL + модельное whole-body управление;
- IFM (arXiv:2311.02304) — имитация и дообучение MPC;
- RL + Model-based Control (arXiv:2305.17842);
- Hybrid LMC (arXiv:2204.03159) — гибрид обучения и модельного
  управления (колёсный гуманоид);
- Merging model-based control with multi-agent RL (arXiv:2606.06011).

**Свежие акценты — многокритериальность и энергия:**

- PROMO (arXiv:2610.01260) — preference-conditioned multi-objective RL;
  **намерение оператора** задаётся как runtime-вход для политики;
- LoComposition (arXiv:2606.15896) — снижение CoT на 56 % без gait-приоров;
- Energy-Efficient Gait Adaptation via HRL (arXiv:2610.10297) — минимизация
  CoT, zero-shot sim-to-real;
- PAMORT (arXiv:2610.05819) — multi-objective RL для переноса груза
  (Unitree Go2);
- Walking on Roofs (arXiv:2610.12272) — базовые замеры **Unitree Go2** в
  новых условиях; прямо отмечают, что нужны RL-походки.

## 2. Пробел (с учётом прямых конкурентов)

**Прямой конкурент существует:** «Benchmarking Model Predictive Control and
Reinforcement Learning for Legged Robot Locomotion»
(DOI 10.37099/mtu.dc.etdr/1677) — бенчмарк MPC vs RL; гибриды MPC+RL также
активно публикуются (10.1109/icrom64545.2024.10903592;
10.1109/iccr55715.2022.10053909). Поэтому **«первое сравнение» не
заявляем**.

Не закрыто:

1. Сравнение на **конкретной связке Unitree Go2 + Isaac Sim** с
   **открытым модельным baseline** (IK/TROT на Rust) и **единым
   воспроизводимым протоколом**.
2. **Таксономия дефектов интеграции** (включая архитектурный крен через
   hip) — в бенчмарках метрик этого нет.
3. **Датасет телеметрии** (125 колонок) для сравнения **контроллеров**
   (Kine2Go — про кинематику, а не про сравнение контроллеров).
4. **Нет связи** сравнения с **намерением оператора** (ср. PROMO,
   arXiv:2610.01260) — эргономический аспект не формализован.

## 3. Новизна (формулировки)

1. **Воспроизводимый протокол сравнения** RL-политики и модельного
   IK/TROT-контроллера на **одной платформе** (Unitree Go2, Isaac Sim,
   n=3), с **телеметрией 125 колонок** — то есть сравнение как
   **воспроизводимый артефакт**, а не единичный прогон.
2. **Количественная карта компромиссов** «эффективность ↔ устойчивость»:
   RL — roll 2.3°, дрейф 0.37 м; IK — roll 27.8°, дрейф 1.09 м; рабочая
   область RL 0.1–0.4 м/с против IK ~0.3 м/с; CoT 2.84 vs 2.83.
3. **Таксономия дефектов**: 5 дефектов интеграции + **архитектурный крен
   через hip (roll 50°→8°)** — конкретная инженерная находка, полезная
   разработчикам модельных контроллеров.
4. **Открытый модельный baseline** (IK/TROT на Rust) — точка отсчёта для
   будущих гибридов (RAMBO/IFM-подобных).
5. **Мост к эргономике:** сравнение даёт основу для «намерения оператора»
   как runtime-параметра (как в PROMO) — направление дальнейших работ.

## 4. Как это подавать (осторожно)

- **Не** заявлять «новый алгоритм управления» — это честно
  **методологически-инженерная** новизна (протокол + карта компромиссов +
  таксономия дефектов + открытый baseline).
- В Related Work: «поле сместилось к RL и гибридам; прямые сравнения с
  явным модельным контроллером на одной платформе редки; мы закрываем этот
  зазор воспроизводимым протоколом».
- В Contribution (2–3 пункта, как требует REEPE): (1) протокол и датасет
  телеметрии; (2) карта компромиссов; (3) таксономия дефектов.

## 5. Риски и как усилить

| Риск | Усиление |
| --- | --- |
| «Это просто сравнение» | подчеркнуть **воспроизводимость** + **открытый baseline** + датасет телеметрии |
| Нет sim-to-real | заявить явно как ограничение; добавить как future work |
| Мало моделей RL | добавить 2-й RL-чекпойнт (разные сиды/гиперпараметры) |
| Слабая связь с оператором | добавить пункт про **preference/runtime-параметры** (PROMO) |
