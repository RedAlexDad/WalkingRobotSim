# Декомпозиционный план: Методичка по ROS 2 (6 семестр)

## 1. Концепция задания

**Тема**: Автономная навигация робота с детекцией объектов по заданному маршруту из файла

**Исходный код**: `WalkingRobotSim` — симуляция четвероногого робота (Unitree Go2) в Gazebo с ROS 2, Nav2, YOLO, управлением походкой.

**Суть задания**: Студент получает готовый проект, должен:

1. Развернуть и запустить симуляцию
2. Загрузить массив путевых точек из внешнего файла
3. Заставить робота пройти по ним автономно
4. На каждом waypoint (или по пути) детектировать объекты через YOLO
5. Собрать метрики и сдать отчёт

**На какой месяц рассчитано**: ~30 дней (6 семестр, одно задание)

**Ключевые узлы для запутывания (ловушки)**:

- Waypoint загружаются из файла, формат которого не описан до конца
- Навигация и YOLO конкурируют за CPU — детекция "тормозит" навигацию
- Executor в ROS 2 — SingleThreadedExecutor блокирует action client
- начальная позиция робота в симуляции может не совпадать с картой
- EKF неправильно сконфигурирован — робот "уплывает"

## 2. Декомпозиция этапов методички

### Этап 1: Введение и окружение (3 дня)

| Шаг | Действие                                        | Ловушка                                          |
| --- | ----------------------------------------------- | ------------------------------------------------ |
| 1.1 | Установка зависимостей ROS 2 Jazzy, colcon      | Версия ROS 2 должна совпадать                    |
| 1.2 | Клонирование репозитория, сборка `colcon build` | Не все пакеты собираются без `--symlink-install` |

### Этап 2: Навигация и waypoints (7 дней)

| Шаг | Действие                                                        | Ловушка                                                    |
| --- | --------------------------------------------------------------- | ---------------------------------------------------------- |
| 2.1 | Изучение структуры waypoint: `quadropted_msgs/msg/Waypoint.msg` | Поле `z` — не высота, а задел                              |
| 2.2 | Ручное указание 2-3 точек через RViz                            | WaypointTool публикует в `/custom_goal_pose`               |
| 2.3 | **Загрузка waypoint из файла**                                  | Сервис `/load_waypoints` — вызов через `ros2 service call` |
| 2.4 | **Создание своего файла `.yaml` с 7-10 точками**                | Формат: `waypoints: [{x: ..., y: ..., z: 0.0, yaw: 0.0}]`  |
| 2.5 | Запуск навигации: `make waypoint-navigate`                      | Action client не соединяется — Executor заблокирован       |
| 2.6 | Наблюдение движения робота в RViz                               | Nav2 может не построить путь, если точка вне карты         |

**Запутывающий момент 2.3-2.4**:

- Студенту даётся **неполный** формат файла. В файле не хватает поля `frame_id` или `header`.
- WaypointCollector парсит YAML, но ожидает определённую структуру (вложенность `waypoints:`).
- Если студент ошибётся в структуре — сервис вернёт `success: false` без понятного сообщения.
- Надо разобраться с форматом через чтение исходников `waypoint_collector.py` (строка ~350).

**Запутывающий момент 2.5**:

- При запуске навигации waypoint_collector использует **SingleThreadedExecutor**.
- Action client `FollowWaypoints` не может обработать callback, пока Executor занят.
- Студент должен найти в логах ошибку `"Executor is not spinning"` и пофиксить.
- Решение: использовать `MultiThreadedExecutor` или вынести action client в отдельный поток.

### Этап 3: YOLO детекция (7 дней)

| Шаг | Действие                                         | Ловушка                                                |
| --- | ------------------------------------------------ | ------------------------------------------------------ |
| 3.1 | Запуск YOLO: `make yolo-detector`                | Модель `yolov8n.pt` не скачана                         |
| 3.2 | Проверка детекций: `ros2 topic echo /detections` | Пустой массив, если нет объектов в кадре               |
| 3.3 | **Интеграция: детекция во время движения**       | YOLO на CPU грузит процессор на 80-90%                 |
| 3.4 | **Фильтрация по классам**                        | `target_classes: ["person"]` — неправильное имя класса |
| 3.5 | Визуализация в RViz                              | `/detection_markers` не отображаются                   |

**Запутывающий момент 3.3**:

- YOLO на CPU потребляет почти всё процессорное время.
- Nav2 planner начинает тормозить — контроллер не успевает строить траектории.
- Робот начинает дёргаться или останавливаться.
- Студент должен догадаться ограничить FPS YOLO (параметр `fps: 2` в `yolo_detector.yaml`).
- Если не ограничить — навигация ломается, метрики не собираются.

**Запутывающий момент 3.4**:

- Параметр `target_classes` отсутствует в дефолтном конфиге.
- Студент должен добавить его сам и понять, какие имена классов использует YOLOv8.
- В YOLOv8 классы — это числа (COCO: 0=person, 1=bicycle,...), а не строки.
- В коде используется строковое сравнение — надо найти в `yolo_detector.py` как происходит фильтрация.

**Запутывающий момент 4.1-4.2**:

- Студент замеряет время прохождения 10 waypoint.
- Запускает с YOLO (FPS=30) — навигация тормозит, время = 5 минут.

- Результат: выбор оптимального FPS для баланса "детекция vs навигация".

## 4. Ловушки (запутывающие моменты) — сводка

1. **Waypoint file format**: структура YAML с `waypoints:` ключом, документация умолчала про вложенность
2. **Executor deadlock**: SingleThreadedExecutor не крутит ActionClient, надо MultiThreadedExecutor
3. **YOLO CPU starvation**: детекция на CPU жрёт ресурсы, Nav2 не успевает планировать
4. **FPS throttling**: без ограничения FPS YOLO детекция ломает навигацию
5. **Классы YOLO**: строковые vs числовые, COCO датасет
6. **Начальная позиция**: робот спаунится не там, где ожидает Nav2
7. **EKF drift**: без правильной настройки EKF одометрия уплывает
8. **Namespace**: все топики с префиксом `/robot1/` — привычные `/cmd_vel` не работают
9. **Waypoint coordinates**: система координат `map`, а не `odom` — перепутать легко
10. **File not found**: путь к файлу waypoint должен быть абсолютным или известным для пакета
