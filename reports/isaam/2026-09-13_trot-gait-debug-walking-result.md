# Отчёт: отладка TrotGait — устойчивая ходьба Go2 в Isaac Sim

- **Дата:** 13 сентября 2026
- **Ветка:** `feat/isaam-research`
- **Статус:** достигнута устойчивая ходьба (без падений), остаточная дуга
- **Итог:** робот проходит ~4.8 м вперёд, Z стабильна (std 0.017 м),
  дрейф по Y снижен с 2.82 до 1.56 м

---

## 1. Задача

Довести математический IK/TROT-контроллер (Rust, ROS2) до устойчивой
ходьбы Unitree Go2 в Isaac Sim 6.0.1 / IsaacLab 3.0. Исходно робот падал
сразу после перехода в режим TROT.

## 3. Диагностика (по усиленному логу)

Первым шагом включено максимальное логирование
(`src/isaac/run_sim_telemetry.py`): структурированный `[SIM] REPORT`
(поза, углы, `joint_err`, fps, статус IMU), детекция NaN/Inf, лог смены
команды, публикация IMU в `/robot1/imu`. Исправлено время шага
(`timeline.get_current_time()` застревало → `step·physics_dt`).

По логам и численной модели походки (порт в Python) выявлены три
корневые причины падения.

### Проблема 1. Дрейф стопы в stance → насыщение IK

**Симптом:** робот падает за ~1–2 с в TROT; `joint_err` до 1.4 рад;
команда `calf = 0` (нога полностью выпрямлена).

**Причина:** в `TrotStanceController::position_delta` скорость стопы
считалась как `-(step_dist/4)/(dt·stance_ticks)`. Делитель
`stance_ticks` — длина ОДНОЙ stance-фазы (9 тиков), но в трот-расписании
нога стоит на земле 3 фазы подряд (27 тиков). Стопа уезжала назад втрое
дальше, чем возвращал swing (`foot_x` до −1.2 м), IK уходил в насыщение.

**Решение:** физически корректная скорость стопы в системе тела —
`velocity = -cmd_vel` (стопа фиксирована в мире) + прежняя
z-компенсация. Файл: `quadropted-core/src/controllers/trot/stance.rs`.

### Проблема 2. Накопление IMU-компенсации

**Симптом:** крен/тангаж накапливались, hip рос до clamp ±0.3 → закрутка.

**Причина:** компенсация (поворот стоп по крену/тангажу) применялась к
`self.foot_locations` каждый тик — повёрнутые стопы становились входом
stance следующего тика.

**Решение:** компенсация применяется только к копии стоп для IK, не к
состоянию походки.

### Проблема 3. Инвертированный знак IMU-компенсации

**Симптом:** робот переворачивался (крен до 180°).

**Причина:** `comp = kp·(0−θ) = −kp·θ`, а применялся `R(−comp) =
R(+kp·θ)` — компенсация усиливала наклон вместо устранения.

**Решение:** применяется `R(comp) = R(−kp·θ)`, `kp` поднят 0.15 → 1.0.

### Проблема 4. Постоянный момент крена/курса

**Симптом:** робот уходил по дуге (дрейф по Y, медленный поворот yaw).

**Решение:** (а) симметричная стойка (убрано смещение переда вперёд
`dx_front = body_length/2 + 0.02`); (б) yaw-стабилизация —
P-регулятор курса `gait_cmd[2] += -0.5·(imu_yaw − desired_yaw)`.

## 4. Результаты

Все прогоны: vx = 0.3 м/с, плоская поверхность, ~17 000–22 000 шагов.

| Прогон | distance_x, м | z_mean, м | z_std, м | max_roll,° | drift_y, м | CoT |
|---|---|---|---|---|---|---|
| База (без IMU) | — (дуга) | 0.232 | — | переворот | 2.5+ | — |
| signfix (kp=1.0) | 5.66 | 0.244 | 0.016 | 31.9 | 3.12 | 2.58 |
| + yaw-стаб. | 4.84 | 0.246 | 0.016 | 35.1 | 2.09 | 2.48 |
| + симметричная стойка | 4.77 | 0.246 | 0.017 | 33.4 | **1.56** | 2.50 |

**Итоговый результат (последний прогон):**
- пройдено вперёд **4.77 м** (путь 6.46 м), падений нет;
- высота стабильна: `z_mean = 0.246 м`, `z_std = 0.017 м`;
- `joint_err` 0.05–0.24 рад; NaN нет;
- дрейф по Y **1.56 м** (снижен с 2.82 м).

## 5. Остаточное ограничение

Крен корпуса ~24° (max 33°) сохраняется. Простой P-стабилизатор
поворачивает стопы горизонтально, но не создаёт возвращающего момента
для выпрямления корпуса; именно этот крен даёт остаточную дугу.
Полное выпрямление требует **capture-point балансира** (смещение стоп
по боковой скорости корпуса). Повышение `kp` до 2.0 дестабилизирует
(робот падает) — проверено.

## 7. Воспроизведение

```bash
# 1. Контроллер в контейнере
docker exec -d walking_robot_sim bash -lc "source /opt/ros/jazzy/setup.bash && \
  source /root/ws/install/setup.bash && \
  ros2 run quadropted_controller_rust robot_controller_node --ros-args -r __ns:=/robot1"

# 2. IsaacLab с телеметрией
GO2_TELEMETRY_TAG=ik bash src/isaac/run_isaaclab.sh --headless

# 3. Команда вперёд
ros2 topic pub -1 /robot1/robot_mode quadropted_msgs/msg/RobotModeCommand \
  '{mode: "TROT", robot_id: 1}'
ros2 topic pub -1 /robot1/robot_velocity quadropted_msgs/msg/RobotVelocity \
  '{robot_id: 1, cmd_vel: {linear: {x: 0.3}}}'

# 4. Разбор
python3 src/isaac/analyze_telemetry.py logs/isaac/telemetry_ik_*.csv --plot
```

## 9. RL-базлайн (в работе)

Для сравнения (статья заявлена как RL vs IK) в `go2_policy.py`
(автономный запуск политики NVIDIA) добавлена запись телеметрии в тот
же CSV-формат: поза, кватернион, скорости, углы/скорости суставов;
`cmd0..2` — команда скорости `(vx,vy,wz)`. Данные берутся из `go2.robot`
(`get_world_poses`, `get_velocities`, `get_dof_positions/velocities`)
через `wp.to_torch`. Коммит `cdca72b`.

**Статус:** первый прогон дошёл до политики (телеметрия писала CSV), но
падал на индексации `wp.array` — исправлено. Повторные запуски
`go2_policy.py` зависают на старте Isaac («Simulation App Starting»);
GPU свободен, зомби-процессов нет — вероятно, залипшее состояние Kit
после первого прерывания по `timeout`. Требуется отладка запуска
(сброс кэша Kit / запуск через `setsid` без `timeout`).
