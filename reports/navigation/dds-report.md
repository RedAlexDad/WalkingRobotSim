# Отчёт: DDS между хостом и контейнером

- Проект: `WalkingRobotSim`
- Дата: 2026-10-28
- Статус: решение принято, правка подготовлена
- Связанные файлы: `src/docker/cyclonedds.xml`, `~/.cyclonedds.xml` (хост)

---

## 1. Постановка

При запуске `make gazebo RVIZ=ergonomic` лог заполняется строками
`Exception sending a multicast message: Network is unreachable` — по одной
на каждое сообщение. Одновременно часть инструментов на хосте (RViz,
русская панель) не видит топики контейнера, хотя другие видят. Требовалось
понять причину и включить устойчивую связь хост ↔ контейнер, не выводя
DDS в локальную сеть.

---

## 2. Факты

1. Контейнер запущен с `NetworkMode=host`: у него и у хоста общее сетевое
   пространство имён. `lo`, `wlp13s0` (192.168.50.229/24), `eno1`,
   `docker0` — одни и те же интерфейсы.
2. В контейнере: `RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`,
   `ROS_DOMAIN_ID=0`, `CYCLONEDDS_URI=file:///cyclonedds.xml`.
3. `/cyclonedds.xml` (монтируется из `src/docker/cyclonedds.xml`):
   только `lo` и `DontRoute=true`.
4. На хосте: тот же RMW, тот же домен, `CYCLONEDDS_URI=~/.cyclonedds.xml`
   с **тем же** содержимым: `lo` + `DontRoute=true`.
5. Ошибка возникает на каждом `publish`, а не при старте.

---

## 3. Гипотезы

- **H1. Docker блокирует multicast (NAT, bridge).** — *Отвергнута.*
  Контейнер в `network=host`, NAT и bridge не участвуют; трафик идёт через
  общий `lo`.
- **H2. `DontRoute=true` запрещает маршрутизацию, поэтому multicast-отправка
  на `lo` завершается `ENETUNREACH`.** — *Принята.* Флаг выставляет
  `SO_DONTROUTE`; для multicast нужен маршрут, которого при этом флаге нет.
  Ошибка повторяется на каждом сообщении, что совпадает с поведением.
- **H3. `lo`-only изолирует хост от контейнера.** — *Отвергнута.*
  При `network=host` `lo` общий: и хост, и контейнер видят один и тот же
  loopback. Unicast-обнаружение по нему работает — поэтому часть
  хостовых инструментов топики видела.
- **H4. Ошибки косметические и на доставку не влияют.** — *Принята
  частично.* Unicast-доставка работает, но multicast-обнаружение — нет:
  новые участники могут не находить друг друга, а лог забивается так, что
  полезные сообщения теряются.

---

## 4. Решение (вариант 1)

Убрать `DontRoute`, оставить интерфейс `lo`. Этого достаточно: хост и
контейнер в одном сетевом пространстве, `lo` общий, а в локальную сеть
DDS не выходит — требование «не светить трафик в LAN» выполняется.

```xml
<CycloneDDS>
  <Domain>
    <General>
      <Interfaces>
        <NetworkInterface name="lo" multicast="true" />
      </Interfaces>
    </General>
    <Discovery>
      <ParticipantIndex>auto</ParticipantIndex>
      <MaxAutoParticipantIndex>100</MaxAutoParticipantIndex>
    </Discovery>
  </Domain>
</CycloneDDS>
```

Правки:

1. `src/docker/cyclonedds.xml` — убрать `<DontRoute>true</DontRoute>`
   (монтируется в контейнер как `/cyclonedds.xml`).
2. `~/.cyclonedds.xml` на хосте — то же изменение, чтобы хостовые узлы
   не сыпали теми же ошибками.
3. Перезапустить узлы: конфиг читается при создании участника DDS.

---

## 5. Риски

| Риск | Оценка | Смягчение |
|---|---|---|
| Multicast пойдёт в LAN | низкий | интерфейс только `lo`, физические интерфейсы не перечислены |
| Другие ROS 2 системы на хосте увидят домен 0 | низкий | домен не меняется, изоляция по `lo` сохраняется |
| Правка глобального `~/.cyclonedds.xml` повлияет на другие проекты | средний | изменение минимальное: снят один флаг; откат — вернуть строку |
| Узлы не перезапущены — правка не применилась | средний | проверка по логу и `ros2 topic list` с хоста |

---

## 6. Проверка (выполнено)

1. Симуляция запущена с `RVIZ=false`.
2. В логе **0** строк `multicast ... unreachable` (до правки — на каждое
   сообщение).
3. Издатель ИМ и коллектор запущены в контейнере.
4. На хосте `ros2 topic list --no-daemon` показывает `/im_confirm`,
   `/im_event`, `/im_obstacles`, `/im_path`, `/im_robot`, `/im_state`,
   `/im_status`, `/im_waypoints`, `/waypoint_state`.
5. `ros2 topic echo /waypoint_state --once --no-daemon` вернул
   `{"count": 0, "active": false, ...}` — живое сообщение из контейнера.
6. `ros2 topic echo /cafe_map --field info.width --once --no-daemon`
   вернул `191` — latched-карта доставлена.
7. RViz на хосте получил карту (`Trying to create a map of size 191 x 447`)
   и держит 31 FPS.

Замечания:

- `ros2` на хосте без `--no-daemon` показывал пустой список: демон хранил
  старое состояние после смены конфигурации. Лечится перезапуском демона
  или флагом `--no-daemon`.
- Вид карты в хостовом RViz (Lyrical) не применился — карта отрисовалась
  мелко. Это различие версий/разбора конфига, к DDS отношения не имеет;
  для рисунков используется RViz в контейнере.

## 7. Ограничения

- Правка проверяется только на этой машине (`wlp13s0`, `eno1`); на другой
  конфигурации сетевых интерфейсов решение не зависит от их имён, так как
  используется только `lo`.
- Если понадобится связь с другой машиной (не с хостом), `lo` недостаточно —
  потребуется добавить физический интерфейс или unicast-peers. Это отдельная
  задача.
- `DontRoute` мог быть добавлен намеренно (изоляция). Если причина была в
  безопасности, снятие флага нужно согласовать; в рамках этой задачи
  изоляция сохраняется за счёт `lo`.

---

## 8. Итог

Причина ошибок — `DontRoute=true` при multicast на `lo`, а не Docker и не
изоляция контейнера. Связь хост ↔ контейнер уже идёт по общему loopback;
снятие флага убирает поток ошибок и делает обнаружение устойчивым, не
расширяя DDS на локальную сеть.

Статус: проверено на стенде.
